## 1. 目标与固定检索路径

产品本质（方向文档）：**可更新、可回溯、需要时能被 AI 抛来的记忆**。本方案是「抛来」的落地：

```text
问题 → searchSegments（关键词 LIKE + 段向量余弦，RRF 融合）
     → top 3~5 命中 → getSegmentDetail 组装证据
     → LLM 只依据证据作答：一段完整回答 + 引用段 id（不给 steps）
     → 画布一次性点亮引用段 → 点球破裂 → 截图 + 续讲
```

方向文档钉死的检索路径原文：「SQL / 向量粗筛 → 双链扩展相关记忆 → 定位窗口片段与事件 → 按需调截图核验 → AI 组织语言解说」。双链扩展在 v1 由检索过滤参数（标签 / 双链名）与画布高亮承担，不单独做扩展步。

一次问答 = 1 次初始解说调用 + 每点开一个球 0..N 次续讲调用。

**拒答纪律（Evidence or silence）**：没有证据就说「信息链里没找到」，不许编（继承旧实施提案的底线；其仍在册决策 D31–D35 不受本方案影响）。

## 2. 三幕交互规格

```text
幕一 · 常驻图谱
  窗口球 = chain_segment（已收口段），球上带标签（chain_tag）
  双链球 = chain_link；边 = chain_link_seg（多对多）
  默认最近 7 天，过滤超短段；可拖可缩，就是一张活图谱。

幕二 · 提问 → 回答 + 点亮证据（P7：不分步）
  输入问题 → 代理调 API → 右侧回答栏**一次给完整回答**，
  下面列引用（时间 · 应用 · 一句「那是什么」）。
  画布同步一次性执行：zoomToFitNodes（把引用的段框进视野）、
  selectNode + dimmedNodeIds（引用的段点亮、其余调暗）、
  引用到的段之间的双链边亮起。
  工程约束：LLM 只产出回答文字 + 引用的段 id；画布动作由前端按引用
  确定性执行——LLM 不直接发画布指令，坏了好查。

幕三 · 点球 → 破裂 → 续讲
  点命中的窗口球 → 球位展开证据面板（v1 诚实简版：缩放淡入）：
  段内时间轴 + 嵌入的截图缩略图（点缩略图开原图）
  → 触发 narrateSegment(segmentId) 续讲（S4 起带截图）→ 落进解说栏。
  点双链球 = 聚焦 + 高亮它连的所有窗口球（列表视图后置）。
```

**呈现口径（2026-10-27 拍板，契约 v0.12 §2.2）**：时间轴**只出有证据的点**（有截图或有内容），事件点（点击 / 滚轮 / 打字 / 移动暂停）**不上界面**——它们是触发与统计的原料，留在库里。没拍到证据的段在时间轴上就是一段没有锚点的区间，不编造占位点。

## 3. 画布实现（内核复用，零改内核）

Foam 内核是独立 Lit 组件（`src/renderer/foam/foam-graph.ts`，vendored，不在冻结范围），公共 API 与三幕需求对照（2026-10-26 已逐一核实）：

| 需求 | 现成 API |
| - | - |
| 默认展示 | `graphData`（新 adapter：链表 → GraphData） |
| 聚焦命中球 | `zoomToFitNodes(ids)`（F8）+ `selectNode()` |
| 其余调暗 | `dimmedNodeIds: Set`（F4 只调暗不删） |
| 点球 | `node-click` / `node-open` CustomEvent（F7 单双击拆分） |
| 操纵图谱 | 以上全是响应式 `@property`，回答返回后一次性改属性 |
| 布局稳定 | `seedPositions` + `graph-settled`（F5） |

两个**未验证点**（S2 实现时验，不现在拍）：

1. 新页节点类型（`segment` / `link`）能否走 `deriveNodeTypeFilters` 从模型派生（看代码路径应该能，未跑过）；
2. 双链边单独高亮的粒度——不行就整集合（段 + 链）一起选中，视觉同样成立。

## 4. S1 代理核心（范围明细）

- **位置**：`src/chain/agent/`（main 侧，只读链表）。
- **两个入口**：
  - `ask(question)` → `{ answer: string, citations: [{ segmentId, at, app, title, why }] }`：
    **一段完整回答 + 它引用的窗口段**（P7，不拆 step）。`at` / `app` / `title` 由服务端从命中段行填好，
    前端不用再查库；`why` 是模型对这一段的一句「那是什么」。引用上限 **6 条**（初值，超了按相关度截断）；
  - `narrateSegment(segmentId)` → 针对单段的续讲（S4 前纯文本；S4 起带该段证据截图）。
- **检索**：问题全文进 `text`（`normalizeOcrSql` 口径）+ bge 段向量（`src/chain/index.ts` 现有会话）双路 RRF；`limit` 取 5~10。
- **证据组装**：命中段 → `getSegmentDetail()` → 每段带起止时间 / 应用 / 标题 / 命中原文片段（截 ~500 字）/ 标签 / 双链。
- **出云**：`redact.ts` 新增 `ChainAskPayload` / `ChainNarratePayload`（证据直传，见 §0.1），`LlmClient` 加 `completeAsk()` / `completeNarrate()`；与派生层共用确认门、日账、退避与 abort。
- **解析纪律**：照抄派生层 `parse.ts`——只信字段与上限，结构不对整次失败，不当空结果。
  引用纪律：`citations[].segmentId` **必须落在本次检索命中的集合里**，编造的整条丢弃（剥离后若一条不剩，
  与「没找到证据」同样处理）；`answer` 缺失或不是字符串 → 整次失败。
- **拒答**：无命中 / 证据不足 → 固定文案「信息链里没找到」，不调 LLM 编话。

## 6. 风险与缓解

| 风险 | 缓解 |
| - | - |
| 召回质量：中文 LIKE 无分词；短问题 vs 6000 字段正文余弦一般（实测「聊天记录继续项目」0.552 命中第一，可用但不保证） | 双路 + 标签 / 双链过滤兜底；不够再上「LLM 先改写检索词」（P1 备选，不进第一版） |
| 编造 | 只喂证据 + 强制引用 id + 无证据拒答；证据卡永远在场供人核 |
| 延迟体感（LLM 数秒） | 回答栏「在想」态；**引用列表可以先出现**（它来自检索结果，不等生成）——等回答落栏时证据已经在那儿了 |
| 多模态格式未查证 | S4 实现时查当时文档；查不到就推迟 S4，S1–S3 不受影响 |

## 7. 明确不做（第一版）

弱主动（S5 单列）、**逐步解说 / 步骤动画**（P7 取消，不做「随解说一步步揭开」）、流式输出、多轮对话历史、语音输入、FTS 索引 / 分页、问题改写（P1 备选）、个人记忆系统（另一套系统，接入前先跟拍板人定口径）、改冻结管线、为冻结部分建新表或设置键。
