# 测试与验收

> `AGENTS.md` 的外链细节，按需读。

## 工具与测试节奏

- 工具（M1 定稿）：`vitest` 单元/集成 + `Playwright` 做 Electron E2E。
- **只跑一处**：每次提交前跑一次 `npm test` + `npm run typecheck`；**开 PR、合并前不再重复跑**（分支是 squash 合并的，main 上的结果就是这一次）。
- 结果如实报：命令 + 通过 / 失败摘要写进交付说明。失败不伪装成通过、不改验收标准、不静默降级。
- 只有改了代码才跑（`src/` / `tests/` / `scripts/`）；只改文档等非代码文件免跑。

## 用例纪律

- 新行为配用例；修 bug **先复现再修**，配回归用例。
- **时间解耦**：日/周/月窗口、静默时段、冷却逻辑一律注入可替换时钟；用例固定时间戳，禁止依赖「现在几点」。
- **静默时段默认值单一来源**：`23:00–08:00` 只在本条定义；技术方案 §6.3 与代码默认值一律引用此处，改这里即全局生效。
- **只用合成数据**：不把真实截图/OCR 文本写进仓库或测试夹具；临时产物进 `.tmp/`（gitignore，跑完清理）。
- **E2E 不启真实录屏 / OCR / 网络**：开关与状态类用例用假采集 `GOTCHA_FAKE_CAPTURE=1`（同时要求 `GOTCHA_USER_DATA` 临时目录、非打包态），并断言 `events` 行数不增长；图谱归纳链路再加 `GOTCHA_FAKE_LLM=1`（同样三条件，输出确定性且能过 `validateInduction`），用测试钩子 `__gotchaTest.fakeLlm()` 断言请求次数（确认门前 / 暂停后必须零新增）。**在线归属链路**（`graph-online.spec.ts`）再加 `GOTCHA_FAKE_EMBEDDING=1` 注入确定性假向量，别加载真模型（模型目录可故意指到不存在的路径）；60s 一轮的在线运行时用 `__gotchaTest.onlineTick()` 直接跑 `runOnce()`。全局热键无法用合成按键触发，走假采集模式下主进程的 `__gotchaTest` 钩子（见 gotchas）。
- **图谱 E2E**：假采集 + 假 LLM 跑「确认出网 → 立即归纳 → sigma 画布出现节点（`#node-count` 的 `data-nodes` + `window.__gotchaGraphView.count()`）→ 来源可溯 → 点击节点侧栏成员事件 →「在时间线中查看」定位到节点日期 → 设置抽屉保存 → 暂停零请求」（`tests/e2e/graph.spec.ts`）。画布交互不按像素点击：`__gotchaGraphView.select(id)` 走与 `clickNode` 相同的 `openNode` 路径。
- **隐私用例**：脱敏管道有 golden 用例（密钥/token/证件号/手机/卡号/邮箱/IP/URL 参数）；黑名单进程命中整帧丢弃要有断言。
- 不许注释用例、加跳过标记、放宽断言来「变绿」。
- **空用例不构成验证**：`npm test` 零断言（或 `expect(true)` 类凑数）通过不算通过；任何阶段首次过闸门至少含 1 条真实行为断言。
- 若维护用例总数：新增/删除用例必须同步计数。

## 验收

- 以技术方案 §7 的出口标准为准，逐条可复现（命令 + 预期输出）。
- 阶段出口做完一条勾一条，不攒到最后。
- 性能基线：CPU < 3%（技术方案 §8）；内存/启动目标 M1 实测后写进本节。

## 出问题怎么报

- 测试失败如实报：命令、失败用例、报错原文（脱敏后）。
- 先最小复现，再判断是代码还是环境。
