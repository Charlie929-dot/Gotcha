## 0. 一句话

**信息链负责「当时具体发生了什么」，个人记忆负责「这些加起来说明你是谁」；图谱只画信息链里的窗口球与双链球，事件和截图留在窗口内部，Hindsight 只站在第二层。**

两条线只通过「筛选后的内容 + 来源引用」通信。AI 代理是唯一编排者：先由个人记忆判断「什么与你相关」，再由信息链找出「当时具体发生了什么」，最后用事件截图核验。

## 1. 这次修正了什么

### 1.1 旧模型的问题

上一版把三件事揉在了一张图里：

| 被揉在一起的东西 | 实际是什么 | 后果 |
| - | - | - |
| 主题（theme） | 对一组时刻的**语义聚类**，成员关系是向量相似度推断 | 被画成「知识节点」，推测看起来像事实 |
| 时刻（moment） | 一段窗口占用的**投影** | 被当成语义层的一等公民，和主题抢同一个画布 |
| 事件（event） | 一次采集观测，截图与 OCR 的载体 | 被要求承担「归纳意义」，或反过来被完全藏掉 |
| 个人记忆（Hindsight） | 关于人的经历、偏好、长期观察 | 没有独立位置，和主题归纳混在一起 |

核心错误不是「图画得不好」，而是**把「记录事实的信息链」和「形成关于你的记忆」当成了同一套系统**。两套系统的证据标准、更新频率、可错性和删除语义都不同，合并之后必然互相污染。

### 1.2 新模型的四条硬边界

1. **图谱只表达信息链**：只有窗口球、双链球两类节点，以及「窗口包含双链」的成员边。没有主题节点、没有事件节点、没有主题相似边。
2. **事件与截图留在窗口内部**：事件是截图触发机制与时间锚点，不承担归纳意义；平时不上主图，核验时才下钻。
3. **主题聚类不进入图谱**：语义聚类是解释，不是观测。旧主题图保留为 legacy 视图，新图不读它；是否最终退役另拍板。
4. **个人记忆独立成层**：只接收筛选后的内容与来源引用，不复制原始事件、鼠标轨迹和截图；Hindsight 是候选实现，不是核心依赖。

## 2. 总架构

### 2.1 两条线

```text
┌─ 采集 ─────────────────────────────────────────────────────────┐
│ 前台窗口 / 截图 / OCR / UIA / 触发信号（前台切换已批；剪贴板/点击等待 D34 扩展拍板） │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼
                 L0 events（观测记录，不是真理）
                           │ 按 app + 标题 + 相邻 ≤90s 分组
                           ▼
        ┌──────────── 信息链（第一层）────────────┐
        │ 窗口球 W：一段前台窗口占用               │
        │   ├─ 内容：OCR/UIA 文本、摘要            │
        │   ├─ 证据点：事件时间锚 + 截图           │
        │   └─ 双链球 L：窗口内容里出现的可复用单元 │
        │ 窗口 ↔ 双链：多对多成员边（带出处）       │
        └──────────────────┬─────────────────────┘
                           │ 只传：筛选后的内容 + 来源引用
                           ▼
        ┌──────────── 个人记忆（第二层）──────────┐
        │ 经历 / 偏好 / 观察 / 心智模型            │
        │ 每条都带 sources；可更新、可过期、可删除  │
        │ 候选实现：Hindsight（retain/recall/reflect）│
        └──────────────────┬─────────────────────┘
                           │ 相关性判断 / 候选记忆
                           ▼
                       AI 代理（唯一编排者）
                           │ 需要时回信息链取证据
                           ▼
              窗口 → 事件点 → 截图 + OCR 原文
```

### 2.2 调用关系

| 谁调用谁 | 传什么 | 不传什么 |
| - | - | - |
| 信息链 → 个人记忆 | 窗口摘要、双链球名称、时间、`source_ref` | 原始 OCR 全文、鼠标轨迹、截图二进制 |
| 个人记忆 → AI 代理 | 相关记忆条目、置信度、来源引用 | 无来源的断言（必须标注 inferred） |
| AI 代理 → 信息链 | 关键词 / 双链球 / 时间窗 / 窗口 id | 不直接改 L0 |
| AI 代理 → 用户 | 自然语言 + 可点击的来源 | 不把推测写成事实 |

### 2.3 降级矩阵

任何一层坏掉，另外的入口必须还在：

| 缺失 | 仍然可用 | 明确提示 |
| - | - | - |
| LLM / API key | 本地双链提取、图谱、检索、窗口下钻 | 「新双链暂不提取」 |
| 本地向量模型 | 精确别名匹配、FTS、图谱 | 「语义匹配不可用」 |
| Hindsight / 个人记忆服务 | 信息链全部功能 | 「个人记忆暂不可用」 |
| 双链提取整体失败 | 窗口、事件、截图、检索 | 图谱只显示窗口球，不伪造双链 |
| 截图缺失 | 窗口、OCR 文本 | 「证据帧未保存 / 已过期」 |

## 3. 第一层：信息链

### 3.1 三个层次：观测 / 投影 / 解释

「事实」在本文里一律理解为**系统观察到的记录**，不是客观真理。UIA、OCR、窗口标题都可能错；所以每一层都要保留来源，最后靠截图核验。

| 层 | 内容 | 可错性 | 能否重建 | 例子 |
| - | - | - | - | - |
| L0 观测 | `events`：时间、app、窗口标题、OCR/UIA 文本、截图路径、敏感标记 | 采集/识别会错 | 不能凭空重建，只能重新采集 | 16:20:03 在 VS Code 看到某段报错 |
| L1 投影 | 窗口切分、双链提及、成员边 | 规则误差 | 可按版本重算 | 这段窗口里出现了「记忆系统」 |
| L2 解释 | 窗口摘要、主题、个人记忆、AI 解说 | 推断会错 | 可重算/可修正 | 「用户最近在持续研究可回溯记忆」 |

硬规则：

- L1/L2 不能反向改写 L0。
- 每条 L1 结论必须能指回至少一个 `event_id`；指不回去就不算信息链内容。
- 每条 L2 结论必须能指回来源，或显式标「推测」。
- 「没有证据」不等于「事情没发生」；只能显示「没找到 / 未记录」。

### 3.2 窗口球

**定义**：一段连续的前台窗口占用，是信息链的一等展示单位。它回答「这一段时间在哪个窗口、内容如何变化」，不回答「这件事属于什么主题」。

**切分口径（沿用现有时刻算法，先不换）**：

- 同 `app` + 同 `window_title`；
- 相邻事件间隔 ≤ 90s；
- 同一本地日（`day_key`）；
- 在线路径用 `settleMs = 90s` 避免把还在生长的窗口先落成半成品。

**字段**：

| 字段 | 含义 | 事实性 |
| - | - | - |
| `id` | 内部主键，展示为 `W0001` | 程序生成 |
| `start_ts` / `end_ts` | 窗口占用起止 | 观测时间 |
| `day_key` | 本地日，日历归属用 | 派生 |
| `app` / `window_title` | 前台窗口元数据 | 观测 |
| `event_ids` | 窗口内的证据点 id（JSON） | 观测引用 |
| `ocr_summary` | 去重截断的内容摘要 | 派生，不是原文 |
| `sensitive` | 是否含敏感内容（由成员事件聚合） | 标记 |
| `segmentation_version` | 切分规则版本；第一版全为 1 | 派生 |
| `superseded_by` | 被哪个新窗口取代（重新切分时） | 派生 |

**ID 与重建**：

- 内部 ID 用整数主键；展示 ID（`W0001`）由主键派生，不暴露给用户设计。
- 窗口是派生投影，不是不可变事实；重新切分必须带 `segmentation_version`，旧窗口标记 `superseded_by`，不物理删除，避免双链/个人记忆的来源引用断链。
- 跨午夜窗口暂沿用「按本地日切开」；是否改成「一个窗口跨日」列为待拍板项，不在第一版改。

**敏感窗口**：

- 命中敏感规则的窗口不提取双链、不出云、不显示原文；
- 图谱上显示为「内容已保护」的灰球；
- 事件行与时间戳保留，截图按 D10/D19/D32 的既有口径处理。

### 3.3 证据点与截图

**定义**：证据点是窗口内部的一次可核验观测，挂在时间轴上；它不是知识节点，也不是图谱节点。

当前实现与目标形态的差距要说清楚：

| 你描述的「事件点」 | 当前能力 | 差距 / 处置 |
| - | - | - |
| 移动鼠标 | 未采集 | 需要全局输入钩子；属 D34 扩展，另行拍板 |
| 滚轮后暂停 | 未采集 | 同上 |
| 左键 / 右键 | 未采集 | 同上 |
| 定时 / 帧差采样 | 已实现 | 当前 `events` 即这类观测点 |
| 前台窗口切换补采 | D34 已批准方向，尚未全量实施 | 可作为新的 `kind` 接入 |
| 截图挂在事件点 | `events.shot_path` 可选；默认只存 OCR | 复用现有列；代表帧按 D32 另行实施 |

设计上留好扩展位，但不把未拍板的采集面偷渡进来：

- 证据点统一带 `kind`：`frame_diff` / `focus_change` / `click` / `wheel_pause` / `clipboard` / `url` / `manual`；
- `events` 现有行视为 `frame_diff`（或 `capture`），不因新增类型而迁移；
- 鼠标/滚轮/点击若实施，必须单独过隐私与性能闸门，不默认开启。

**截图策略**：

- 每个证据点可以有一张截图（`shot_path`），也可以没有；
- 每个窗口至少尝试一张代表帧（D32），敏感窗口不存；
- 过期只删截图文件、置空路径，**事件行、时间戳、来源引用永不删**；
- UI 必须区分「没有截图」与「截图已过期」，不能假装有证据。

**核验路径**：

```text
双链球 → 所有包含它的窗口 → 选中窗口
  → 窗口内事件时间轴（时间 / kind / 截图缩略 / OCR 片段）
  → 点某个事件 → 原始截图 + OCR 原文 + 采集时间
  → 截图缺失时明确显示「证据帧未保存」，只给文本与时间
```

### 3.4 双链球

**定义**：双链球是一个**在窗口内容里实际出现、可复用 ID 的内容单元**。它可以是概念、实体、文件名、报错码、项目名、人名等；它连接所有包含它的窗口。

它和旧主题的区别是根本性的：

| 维度 | 旧主题（theme） | 双链球（link unit） |
| - | - | - |
| 成员关系 | 向量相似度聚类 | 窗口文本里**实际出现** |
| 证据 | 质心 / 相似度分数 | `event_id` + 原文片段 |
| 可否多归属 | 一个时刻可属多个主题 | 一个窗口可含多个双链，天然多对多 |
| 标题来源 | LLM 命名 / 兜底 | 原文表面形式 + 规范化 |
| 错了怎么发现 | 抽样看合并准确率 | 点开出处，对照截图 |
| 在图上的角色 | 语义节点 | 内容索引球 |

**存在性硬规则（最重要的一条）**：

> 没有原文出处的双链球不存在。LLM 可以提议候选，但不能凭空造球；候选必须能在该窗口的 OCR/UIA 文本里找到对应片段，否则丢弃。

补充两条硬校验：

- 规范化后为空、或 `quote` 为空 / 在原文里找不到的候选，一律丢弃；不建空球。
- 校验用**原始 OCR/UIA 文本**，不用窗口摘要；摘要是派生，不能反过来当出处。

这条规则是对旧主题图「语义相似就当成员」的纠偏，也是「事实可核验」在数据层的落地。

**双链球的来源（按优先级）**：

1. **用户显式标记**：选中文本 →「记为双链」；最高置信，直接建球/挂接。
2. **本地高精度模式**：引号内文本、书名号、文件路径、URL、代码标识符、报错码、`[[...]]` 形式；只认确定性格局。
3. **LLM 候选提取**：从窗口摘要/文本中提议 `{name, kind, quote}`；必须过原文校验，只作为 `provisional` 候选，不直接当权威。
4. **不做**：用窗口向量聚类生成双链；用主题标题反推双链；把 app 名/窗口标题当双链（它们是元数据，不是内容单元）。

**规范化与合并**：

```text
原文表面形式（surface）
  → NFKC / 去首尾空白 / 全角转半角 / 英文小写
  → alias_key
  → 命中 link_aliases：复用 link_id
  → 未命中：新建 provisional 球，并把 alias_key 写入 link_aliases
  → 与已有球「疑似同一」：进确认队列，不自动合并
```

- 精确 `alias_key` 命中才自动复用（`link_aliases.alias_key` 是主键）；
- 编辑距离/向量相似只用于**提示**「可能同一个」，合并必须有人确认（或用户显式操作）；
- 禁止传递式自动合并（A≈B、B≈C 不代表 A=C）；
- 合并保留 `merged_into`，旧 ID 跟随到存活球，来源引用不断链；别名行迁到存活球，旧 key 仍可追溯；
- 拆分要保留审计：哪些窗口/出处被移到新球。

**字段**：

| 字段 | 含义 |
| - | - |
| `id` | 内部主键，展示为 `L0017` |
| `name_key` | 规范化后的查找键（不唯一；精确查找走 `link_aliases`） |
| `canonical_name` | 展示名 |
| `kind` | `concept` / `entity` / `file` / `error` / `person` / `project` / `other` |
| `status` | `provisional` / `active` / `merged` / `archived` |
| `merged_into` | 合并目标（可空） |
| `first_seen_ts` / `last_seen_ts` | 首次/最近出现 |
| `created_at` / `updated_at` | 审计 |

**窗口↔双链边**：

- 主键 `(window_id, link_id)`；
- `weight` / `occurrences` 只表示「在这段窗口里出现了几次」，不表示语义相关度；
- `provenance_json` 存 `[{eventId, quote, ts}]`，用于侧栏高亮出处；
- `origin` 记 `local` / `llm` / `user`，便于审计与回退；
- 敏感窗口不写边。

### 3.5 图谱：只有两类球

**节点**：

| 节点 | 前缀 | 大小 | 标签 | 颜色 |
| - | - | - | - | - |
| 窗口球 | `w:<id>` | 按持续时长/事件数，对数压缩 | 窗口标题（截断）+ 时间；敏感窗口「内容已保护」 | 中性蓝 |
| 双链球 | `l:<id>` | 按包含它的窗口数，对数压缩 | 规范名 | 琥珀/绿，按 kind 微调 |

**边**：

- 只有 `kind='mention'`：窗口 ↔ 双链；
- 不画主题-主题相似边、不画事件节点、不画窗口-窗口时间边；
- 双链之间的共现关系不落库、不常驻；选中某个双链时，可临时高亮「与它共同出现的双链」，但这是**查看态**，不是图结构。

**布局**：

- 二分图力布局：双链球作为枢纽，窗口球被多个双链拉向不同簇；
- 窗口球不按时间强制排布；时间通过筛选/调暗和独立时间轴表达，避免把「时间近」误读成「语义近」；
- 默认只显示「出现 ≥2 个窗口」的双链球，以及连接到这些球的窗口；一键「显示全部」再展开长尾；
- 未连接任何双链的窗口默认不画，但在时间线/检索里仍可找回；图谱状态栏明确「另有 N 个未连接窗口」；
- 位置 seed 用新表 `graph_positions_v2`（按 `kind + id`），不要复用旧 `node_positions`（旧表的主键是主题 id，会撞）。

**交互**：

| 操作 | 结果 |
| - | - |
| 单击双链球 | 聚焦：高亮所有包含它的窗口；侧栏列出窗口（按时间倒序）+ 每条的出处片段 |
| 双击双链球 | 打开完整侧栏（窗口列表、首次/最近出现、别名、合并/拆分入口） |
| 单击窗口球 | 聚焦：高亮它的双链；侧栏显示窗口内容与证据时间轴 |
| 双击窗口球 | 打开完整窗口侧栏（事件列表、截图、OCR、双链） |
| 点边/出处片段 | 跳到对应窗口的具体事件点 |
| 背景点击 | 退出聚焦 |

**时间**：

- 日历/时段筛选只调暗，不删节点（沿用 D29/D36 的交互）；
- 双链球的聚焦判定：只要有任一成员窗口在时间窗内，就点亮；
- 另设「时间轴」视图（窗口按时间排成一条带），但不把时间边塞进图谱。

**LOD（M3）**：

- 缩到最远：只显示高频双链球（如 ≥5 个窗口）+ 聚合计数；
- 中距离：双链 + 窗口；
- 最近：窗口 + 事件点预览；
- 规模上限与降级策略在 M3 实测后定，不在第一版硬编码。

### 3.6 事实边界

- 窗口标题、OCR、UIA 都可能错；双链的「出现」只证明「这段文本里读到了这个词」，不证明「用户理解了它」。
- 双链的 `canonical_name` 是规范化结果，不是用户原话；侧栏必须能展开原文表面形式与出处。
- 事件截图是核验手段，不是「真相」；截图也可能裁错、过期、被敏感规则拦掉。
- 所有「AI 摘要」都要标为派生；不要把摘要当原文回显。
- 用户纠错（改名、合并、拆分、删除）要留审计，不静默改写历史。

## 4. 第二层：个人记忆

### 4.1 职责

回答这些问题：

- 你是什么样的人、关心什么；
- 你学过什么、做过什么、形成什么经验；
- 你现在可能需要什么；
- 哪些记忆值得被重新提起。

不负责：

- 保存原始屏幕证据；
- 证明「当时到底发生了什么」（那是信息链的职责）；
- 直接改写 L0/L1；
- 在没有来源的情况下生成「事实」。

### 4.2 数据形态

个人记忆不是一张平表，而是四类条目 + 来源 + 反馈：

| 类型 | 含义 | 更新方式 |
| - | - | - |
| `episode` | 一段经历/事件记忆（「上周在调这个报错」） | 追加；可被后续经历补充 |
| `observation` | 从多条记忆归纳出的观察（「最近持续研究可回溯记忆」） | 可被新证据修正；保留支持/反证来源 |
| `mental_model` | 围绕某个问题的长期理解（「他更重视证据可靠性而不是 AI 摘要」） | 可重写；旧版本进历史 |
| `preference` | 明确的偏好/习惯（「不喜欢弹窗」） | 用户确认优先；推测需标注 |

每条记忆至少带：

```text
id, kind, text,
confidence,            -- 0~1，推测必须 < 1
valid_from, valid_to,  -- 时间有效性；过期不等于删除
superseded_by,         -- 被哪条新记忆取代
sources[],             -- window / link / event / user
created_at, updated_at
```

### 4.3 读写

**retain（写入）**：

```text
窗口关闭 / 定时批量
  → 取窗口摘要 + 双链名称 + 时间（已过滤敏感）
  → 判断是否值得记（新信息 / 重复 / 情绪/偏好线索）
  → 写 episode 或更新 observation
  → 附 sources（窗口 id、双链 id、事件 id）
```

**recall（召回）**：

```text
查询 / 当前上下文
  → 语义 + 关键词 + 时间 + 图谱邻域（Hindsight 的 recall 口径）
  → 返回记忆条目 + 来源引用 + 置信度
  → AI 代理再用来源回信息链取证据
```

**reflect（反思）**：

```text
一组相关记忆
  → 生成/修正 observation 或 mental_model
  → 必须列出支持来源与反证
  → 低置信的写成「可能」，不写成「是」
```

**forget / export**：

- 删除一条记忆：删条目 + 来源引用；不删信息链；
- 删除一个窗口/事件：个人记忆的来源引用变悬空，UI 显示「来源已删除」，不静默改写记忆；
- 导出：JSON/Markdown，含来源引用；导入要保留 id 映射或标为 imported。

### 4.4 Hindsight 的位置

**结论：Hindsight 放第二层，不放图谱层，也不放采集层。**

理由：

1. 它的 `retain/recall/reflect`、Observations、Mental models 处理的是「关于人的理解」，不是「原始证据」；
2. 它的观察会随新证据修正，和 L0 的不可改写性冲突；放第二层正好；
3. 它需要的是筛选后的内容，不是全部鼠标事件和截图；放第二层可以强制这个边界；
4. 它坏了不能影响「找东西」——信息链和检索必须独立可用。

**但「适合」不等于「现在采用」**。采用前必须验证（当前仅根据仓库说明判断，未验证）：

| 验证项 | 要回答的问题 | 不通过怎么办 |
| - | - | - |
| 部署 | 能否纯本地运行？是否要 Docker/Python/外部服务？ | 保留内置实现 |
| 数据 | 中文记忆的召回质量如何？规模上限？ | 保留内置实现 |
| 成本/延迟 | 常驻内存、CPU、P95 延迟 | 降级为按需启动 |
| 许可 | 许可证是否允许自用/分发 | 不采用 |
| 导出/删除 | 能否完整导出、按条删除、删除来源后不残留 | 不采用 |
| 出网 | 默认零出网；暂停时零写入/零请求 | 不采用 |

**架构上先留适配器，不绑死**：

```ts
interface PersonalMemoryStore {
  retain(input: MemoryInput): Promise<MemoryId[]>
  recall(query: RecallQuery): Promise<MemoryHit[]>
  reflect(input: ReflectInput): Promise<MemoryItem[]>
  forget(id: MemoryId): Promise<void>
  exportAll(): Promise<MemoryExport>
}
```

- 默认实现：内置 SQLite（`personal-memory.db`）+ 本地向量；先保证「有来源、可删除、可导出」。
- Hindsight 适配器：本地 HTTP/CLI 包装，映射 retain/recall/reflect；不把它的内部存储当事实源。
- 切换实现不影响信息链、图谱、检索。

### 4.5 两层契约

1. **只传筛选后的内容 + 来源引用**：窗口摘要、双链名、时间；不传原始 OCR 全文、截图、鼠标轨迹。
2. **个人记忆不能改信息链**：只能读；要纠错走信息链的显式入口。
3. **来源可悬空**：信息链删除/重建后，个人记忆保留条目但标「来源已删除」；不自动删记忆，也不假装来源还在。
4. **每条记忆有来源或标 inferred**：没有来源的条目不允许以「事实」口吻展示。
5. **暂停语义**：暂停时停止新增派生任务（窗口收口后的双链提取、个人记忆写入、任何 LLM 调用），在途出网 abort、结果丢弃；只读浏览不受影响，恢复后按序补跑。这样既守 D18 的「零出网」，也不会让用户以为「暂停了还在后台整理」。是否允许纯本地的只读维护（不算新增派生）另行拍板；默认不做。
6. **删除传播**：用户删除一条记忆/一个窗口，必须能列出受影响的另一层对象，由用户确认是否级联；不静默级联删除。

## 5. 数据模型

### 5.1 v7：信息链双链层

物理上暂不重命名 `moments`（避免一次性改 10+ 查询与测试），语义上它就是窗口球；新代码的 DTO 用 `WindowDto` 别名。

```sql
-- 双链球
CREATE TABLE IF NOT EXISTS link_units (
  id             INTEGER PRIMARY KEY,
  name_key       TEXT NOT NULL,              -- 规范化后的查找键（不唯一：合并后旧键仍可追溯）
  canonical_name TEXT NOT NULL,
  kind           TEXT NOT NULL DEFAULT 'other',
  status         TEXT NOT NULL DEFAULT 'provisional', -- provisional | active | merged | archived
  merged_into    INTEGER,                    -- 合并目标；旧引用跟随
  first_seen_ts  INTEGER,
  last_seen_ts   INTEGER,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_link_units_name_key ON link_units(name_key);
CREATE INDEX IF NOT EXISTS idx_link_units_status ON link_units(status);

-- 别名：精确命中复用 id；surface 保留原文。
-- 唯一性由 alias_key 保证；canonical_name 本身也写一行 alias，保证「同名不同球」不会出现。
CREATE TABLE IF NOT EXISTS link_aliases (
  alias_key  TEXT PRIMARY KEY,
  link_id    INTEGER NOT NULL,
  surface    TEXT NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_link_aliases_link ON link_aliases(link_id);

-- 窗口 ↔ 双链（多对多，带出处）
CREATE TABLE IF NOT EXISTS window_links (
  window_id       INTEGER NOT NULL,          -- moments.id
  link_id         INTEGER NOT NULL,
  weight          REAL NOT NULL DEFAULT 1,
  occurrences     INTEGER NOT NULL DEFAULT 1,
  provenance_json TEXT NOT NULL,             -- [{eventId, quote, ts}]
  origin          TEXT NOT NULL DEFAULT 'local', -- local | llm | user
  extractor_version INTEGER NOT NULL DEFAULT 1,
  created_at      INTEGER NOT NULL,
  PRIMARY KEY (window_id, link_id)
);
CREATE INDEX IF NOT EXISTS idx_window_links_link ON window_links(link_id);

-- 新图的位置 seed（不要复用旧 node_positions：主键空间是主题 id）
CREATE TABLE IF NOT EXISTS graph_positions_v2 (
  kind       TEXT NOT NULL,                  -- window | link
  entity_id  INTEGER NOT NULL,
  x          REAL NOT NULL,
  y          REAL NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (kind, entity_id)
);

-- 窗口切分版本（为将来重新切分留路；第一版全部为 1）
ALTER TABLE moments ADD COLUMN segmentation_version INTEGER NOT NULL DEFAULT 1;
ALTER TABLE moments ADD COLUMN superseded_by INTEGER;
```

- 迁移 v7 只建表/加列 + 索引，**不在迁移里回填**；回填是独立、幂等、可中断的任务。
- `ALTER TABLE` 前做列存在性检查（沿用现有迁移风格）；down 直接 `DROP COLUMN`。
- `window_links` 不设 SQL 外键：窗口/双链都可能重建，应用层校验 + 悬空检测更稳。
- 双链的 `provenance_json` 是必须字段；没有出处的行不允许写入。
- `link_units.name_key` 不做唯一约束：合并后的源球保留旧键用于追溯；精确查找走 `link_aliases.alias_key`（主键）。

### 5.2 个人记忆库

单独一个 `personal-memory.db`，物理隔离，避免和证据库（`memory.db`）互相污染：

```sql
CREATE TABLE IF NOT EXISTS memory_items (
  id            INTEGER PRIMARY KEY,
  kind          TEXT NOT NULL,               -- episode | observation | mental_model | preference
  text          TEXT NOT NULL,
  confidence    REAL NOT NULL DEFAULT 0.5,
  valid_from    INTEGER,
  valid_to      INTEGER,
  superseded_by INTEGER,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  meta_json     TEXT
);

CREATE TABLE IF NOT EXISTS memory_sources (
  id         INTEGER PRIMARY KEY,
  memory_id  INTEGER NOT NULL,
  source_kind TEXT NOT NULL,                 -- window | link | event | user
  source_id  TEXT NOT NULL,                  -- 如 w:123 / l:17 / e:9876
  quote      TEXT,
  relation   TEXT NOT NULL DEFAULT 'supports', -- supports | contradicts | mentions
  created_at INTEGER NOT NULL
);
-- quote 可空，用表达式索引避免 SQLite 复合主键里 NULL 不唯一的问题
CREATE UNIQUE INDEX IF NOT EXISTS idx_memory_sources_unique
  ON memory_sources(memory_id, source_kind, source_id, coalesce(quote, ''));
CREATE INDEX IF NOT EXISTS idx_memory_sources_memory ON memory_sources(memory_id);

CREATE TABLE IF NOT EXISTS memory_embeddings (
  memory_id  INTEGER PRIMARY KEY,
  model      TEXT NOT NULL,
  dim        INTEGER NOT NULL,
  vec        BLOB NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS memory_feedback (
  id         INTEGER PRIMARY KEY,
  memory_id  INTEGER,
  kind       TEXT NOT NULL,                  -- useful | irrelevant | wrong | pin
  note       TEXT,
  created_at INTEGER NOT NULL
);
```

- `memory_sources.source_id` 用带前缀的字符串，便于跨库、跨重建识别；解析不到就显示「来源已删除」。
- 记忆库可单独备份/导出/删除；删掉它不影响信息链。
- 是否加密、是否与主库同目录，待拍板；默认自用不加密，但导出文件要提示敏感。

### 5.3 迁移与兼容

| 现有对象 | 新定位 | 处置 |
| - | - | - |
| `events` | L0 观测 | 不动；新增证据 `kind` 时用新列/新表，不改旧行 |
| `moments` | 窗口球 | 物理保留；新增 `window_links` 关联；DTO 改名 `WindowDto` |
| `nodes` / `theme_moments` | 旧主题（解释层，非信息链） | 冻结新写入；legacy 视图只读；不迁移进新图 |
| `edges(kind='embedding')` | 旧主题相似边 | 新图不读；legacy 视图保留 |
| `theme_centroids` / `event_embeddings` | 旧主题派生向量 | 不删；新图不需要 |
| `node_positions` | 旧主题位置 | 不删；新图用 `graph_positions_v2` |
| `events_fts` | 检索 | 保留；命中 → 窗口 → 证据 |
| `theme-online-runtime` | 主题在线归属 | 新图稳定后默认停；开关保留一个版本 |
| `graph:global` / `global.ts` | 旧主题图 | 保留 legacy 页；新图走独立通道/页面 |
| `theme-queue` | LLM 串行队列 | 可泛化为双链提取/个人记忆的队列；先复用模式，不急着改接口 |

**迁移顺序**：

1. 建 v7 表，不写数据；
2. 新图页面在 feature flag 后上线，旧图仍是默认；
3. 回填最近 30–90 天的双链，出覆盖率/质量报告；
4. 新图达到验收线后切默认，旧图进「legacy」开关；
5. 观察一个版本，再决定主题管线退役/保留；
6. 最后才考虑把 `moments` 重命名为 `windows`（纯技术债，不阻塞）。

## 6. 管线

### 6.1 窗口构建

沿用 `moment-runtime` / `backfillMomentsForDay`：

- 采集 running 时每 60s 补稳定窗口；
- 打开图谱时全量回填（幂等）；
- 暂停即停；A3 口径（没建过库不建库）不变。

新增：窗口收口后触发双链提取任务（本地优先，LLM 可选）。

### 6.2 双链提取

```text
窗口收口
  → 取窗口成员事件的 OCR/UIA 文本（敏感窗口跳过）
  → 本地高精度候选（引号/路径/URL/代码标识/报错码/[[...]]）
  → 可选：LLM 候选（只提议，必须带 quote）
  → 原文校验：quote 必须能在该窗口文本里找到（规范化后）
  → 规范化 name_key → 命中别名复用 / 新建 provisional
  → 写 window_links + provenance
  → 疑似重复进确认队列（不自动合并）
```

约束：

- 每窗口候选数设上限（如 20），避免长文档爆炸；
- 同一 `(window_id, link_id)` 只一行，重复出现累加 `occurrences` / 合并 provenance；
- LLM 调用受 D22 预算/退避/D24 确认门/D18 暂停约束；
- 失败只跳过该窗口，不回滚窗口，不影响采集；
- 提取器带 `extractor_version`，便于以后重跑。

**质量优先于覆盖率**：第一版宁可少提，也不要造球。漏掉的可以通过用户标记、后续重跑、LLM 候选补齐；造出来的假球会污染整个图。

### 6.3 个人记忆

```text
窗口收口 + 双链稳定
  → 过滤（敏感、无内容、重复）
  → retain：写 episode / 更新 observation
  → 定时/按需 reflect：生成 mental_model / 修正 observation
  → 所有条目附 sources
```

- 默认异步、低优先级、可暂停；
- 不逐事件写记忆，按窗口/批次；
- 出云只走既定脱敏出口；不出云也能用内置本地实现；
- 记忆写入失败不影响信息链。

### 6.4 队列 / 暂停 / 降级

- 复用现有串行队列模式：最多一个 LLM 在途、可合并、可暂停、可恢复；
- 暂停（D18）：停采集 + 停新增派生任务 + abort 在途出网；恢复后按序补，不重复；
- 缺 key/未授权（D24）：任务留在队首零请求，不写兜底假数据；
- 预算/退避（D22）：与主题管线同一套日账，不另起一套；
- 任何失败都不能阻塞窗口构建、检索、图谱只读浏览。

## 7. 找回路径

| 路径 | 入口 | 过程 | 输出 |
| - | - | - | - |
| A 双链探索 | 图谱点双链球 | 双链 → 所有窗口 → 事件/截图 | 带出处的窗口列表 |
| B 关键词 | 检索框 / FTS | 命中事件 → 窗口 → 证据 | 窗口卡片 + 原文片段 |
| C 个人记忆 | AI 代理 / 记忆面板 | recall 记忆 → 来源引用 → 信息链取证据 | 有依据的回答 |
| D 弱提示 | 当前上下文 | 个人记忆相关性 + 信息链精确匹配 → 高置信 | 球轻微脉冲 → 证据卡 |
| E 续上 | 回到同一 app/标题 | 上一次窗口 + 证据 | 被动「上次在这里」 |

共同底线：

- 每条结果都能点回窗口/事件/截图；
- 没有证据就说「没找到」，不编；
- 个人记忆只给候选与理由，最终证据必须来自信息链；
- 检索不依赖双链是否已提取（D31：未归纳不等于不可找回）。

- **数据审计**：迁移前先跑一份「主题标题在成员窗口原文中的可命中率」，用真实数字决定要不要做候选导入，不拍脑袋。

## 9. 分阶段实施与验收

### P0 决策与数据审计（无代码）

做：

- 拍板 §11 的 1–4 项；
- 只读审计真实库：窗口数、每窗口事件数、OCR 质量抽样、候选模式覆盖率、主题标题可命中率；
- 产出迁移报告，不改库。

出口：知道「双链提取大概能覆盖多少窗口」，以及旧主题是否值得做候选导入。

### P1 信息链内核（无 UI）

做：

- v7 迁移；
- 本地双链提取 + 规范化 + 写库 + 合并/拆分审计；
- `queryLinkGraph` DTO；
- 单测：候选/校验/别名/合并/悬空/敏感/幂等。

出口：对一个真实库副本回填 30 天，人工抽样 50 个窗口：

- 双链条目 ≥80% 能在原文找到且语义正确；
- 假球率（原文找不到/明显错）<5%；
- 重跑幂等，不产生重复球/重复边。

### P2 新图谱页（feature flag）

做：

- `links.html` + 适配器 + 侧栏；
- 双链聚焦、窗口下钻、事件截图、时间筛选/调暗；
- 旧图仍默认，新图可切换对比；
- E2E：假提取器跑「窗口→双链→图→下钻」。

出口：新图能完成 A 路径（双链→窗口→证据），且不依赖主题表。

### P3 切换默认与旧图 legacy

做：

- 回填最近 90 天；
- 覆盖率/质量报告达标后切默认；
- 旧图进 legacy 开关；
- 主题在线写入默认停（保留开关）。

出口：连续一周真实使用，A/B 路径都能找回；旧图仍可打开；没有数据被删。

### P4 个人记忆最小闭环

做：

- `personal-memory.db` + 内置 store；
- retain/recall + 来源引用 + 删除/导出；
- 记忆面板（只读 + 反馈）；
- 与 AI 代理的调用契约。

出口：每条记忆有来源或标 inferred；删窗口后来源显示「已删除」；导出可读；无来源断言为零。

### P5 Hindsight spike / 采用

做：

- 本地部署验证（部署/数据/成本/许可/导出）；
- 用同一批窗口摘要跑 recall 对比；
- 通过则接适配器，不通过保留内置。

出口：满足 §4.4 的六项验证；不满足就明确写「不采用」，不静默降级。

### P6 清理与技术债

做：

- 评估主题管线退役；
- `moments` → `windows` 重命名（可选）；
- 删除旧图前先导出/归档；
- 文档收口。

出口：没有两套图同时写；旧数据可导出；回滚路径明确。

## 10. 风险与边界

| 风险 | 表现 | 对策 |
| - | - | - |
| 双链提取造假 | LLM 提议的概念原文找不到 | 原文校验；无出处不写；候选标 provisional |
| 别名误合并 | 「记忆」与「记忆球」被并成一个 | 精确匹配才自动；模糊只提示；合并可撤销；禁止传递合并 |
| 图谱变成毛球 | 每个窗口挂十几个一次性双链 | 默认只显示 ≥2 窗口的双链；长尾可展开；LOD |
| 窗口碎片化 | 标题变化导致一段任务被切碎 | 先沿用现有切分；用双链把碎片重新连起来；切分版本化 |
| 旧主题价值丢失 | 用户习惯了主题图 | legacy 视图保留一个版本；平行跑；不删数据 |
| 个人记忆污染 | 无来源的「你最近在……」 | 强制 sources；低置信标「可能」；用户反馈可纠正 |
| Hindsight 不可用 | 部署重/慢/许可问题 | 适配器 + 内置实现；spike 闸门；不绑核心 |
| 隐私扩大 | 双链名本身含敏感信息 | 敏感窗口跳过；双链本地存储；出云走 redact；可删除 |
| 输入信号偷渡 | 鼠标/滚轮采集未拍板就上 | 第一版不做；D34 扩展单独拍板 |
| 规模 | 10k 窗口 / 50k 双链 | 默认阈值 + LOD + 时间筛选；M3 实测 |

明确不做：

- 不做 3D；
- 不做主题相似边/双链共现边常驻；
- 不做事件节点上主图；
- 不做 LLM 生成语义边；
- 不做云同步/多端；
- 不把 Hindsight 作为强依赖；
- 不在未拍板前扩大采集面（鼠标/剪贴板/URL）。

## 11. 待拍板

1. **双链球的默认创建策略**：本地高精度模式自动建 `provisional`，LLM 候选也只建 provisional（图上可见但带「待确认」），还是全部先入确认队列？
   - 建议：本地高精度自动建；LLM 候选建 provisional；只有「合并/改名」必须确认。
2. **旧主题图的去留**：保留 legacy 一个版本后退役，还是长期保留为「主题视图」？
   - 建议：保留一个版本只读；新图稳定后再决定是否退役；不自动把主题转双链。
3. **鼠标/滚轮/点击是否纳入采集**：这会把「事件点」从帧差观测扩展到输入信号，涉及隐私与性能。
   - 建议：第一版不做；先沿用帧差 + 前台切换；D34 扩展单独拍板。
4. **Hindsight 的采用方式**：先内置最小实现 + 适配器，还是直接上 Hindsight？
   - 建议：先内置，P5 做 spike；通过六项验证再替换。
5. **窗口跨日**：继续按本地日切开，还是一个窗口允许跨午夜？
   - 建议：第一版不改；跨日窗口在日历上按开始日归属，后续再评估。
6. **图谱默认隐藏长尾**：默认只显示 ≥2 窗口的双链 + 相连窗口，未连接窗口只在时间线/检索出现——是否接受？
   - 建议：接受；状态栏显示隐藏数量，一键展开。
7. **个人记忆库的位置与加密**：独立 `personal-memory.db`、默认不加密、导出提示敏感——是否接受？
   - 建议：接受；自用优先简单，后续可加系统级加密。
8. **双链 kind 分类**：先用最小集合（concept/entity/file/error/person/project/other），还是先不分？
   - 建议：先最小集合，kind 只影响图标/提示，不影响查询。

## 12. 验收速查

进入实施前，逐条回答：

- [ ] 这个功能服务「找回 / 续上 / 理解」哪一个真实场景？
- [ ] 它画的是窗口/双链，还是又把主题/事件塞进了图？
- [ ] 每条双链能否点回原文与截图？
- [ ] 没有出处时，系统是否选择「不建球」而不是猜？
- [ ] 归一化/合并是否可撤销、可审计、无传递合并？
- [ ] 双链失败时，窗口/检索/旧图是否仍然可用？
- [ ] 个人记忆是否只拿到筛选后的内容 + 来源引用？
- [ ] 每条记忆是否有来源或标 inferred？
- [ ] 删除窗口/记忆时，另一层的悬空引用是否显式暴露？
- [ ] 是否扩大了采集面/出网面？是否已单独拍板？
- [ ] 规模变大时，默认视图是否会变成毛球？LOD/阈值是否可调？
- [ ] 旧主题图是否可以回退？数据是否未被删除？

## 附录 A：术语

| 术语 | 含义 | 不是什么 |
| - | - | - |
| 信息链 | 窗口、内容、证据点、截图、双链、出处 | 不是「关于你的理解」 |
| 窗口球 | 一段前台窗口占用 | 不是主题，不是知识节点 |
| 双链球 | 窗口内容里实际出现、可复用 ID 的内容单元 | 不是语义聚类，不是主题标题 |
| 证据点 | 窗口内的一次可核验观测（事件 + 截图） | 不是图谱节点 |
| 个人记忆 | 关于人的经历/偏好/观察/心智模型 | 不是原始证据库 |
| 主题 | 对窗口的语义聚类（旧模型） | 不进入新图谱 |
| 观测 | 系统采集到的记录，可能出错 | 不等于客观真相 |

## 附录 B：与旧方案的差异

| 维度 | v1.1 指导方案 / m2 主题图 | 本文 v2 |
| - | - | - |
| 图谱节点 | 主题 + 时刻 | 窗口 + 双链 |
| 边 | 主题相似边 + 成员边 | 只有窗口↔双链成员边 |
| 主题 | 图谱一等公民 | 解释层，legacy 视图，不进新图 |
| 事件 | 默认不上图，侧栏下钻 | 窗口内部证据点，不上图 |
| 双链 | 无（仅 M5 Obsidian 导出） | 信息链核心索引 |
| 个人记忆 | 无独立层 | 独立第二层，Hindsight 候选 |
| 归属 | 向量相似度 + LLM 确认 | 原文出现 + 规范化别名 |
| 主要风险 | 主题误合并、语义边造假 | 双链造假、别名误合并、图谱毛球 |
| 价值落点 | 图谱即理解 | 图谱导航证据；理解交给个人记忆 + AI |

---

**最终判断标准：图谱不是记忆本身，而是回到证据的索引；个人记忆不是事实，而是有来源、可修正的理解。两者分开，才能既找得到，又不把人编造成数据。**
