# 安全、隐私与权限

> `AGENTS.md` 的外链细节，按需读。

## 三条硬前提

- 采集**默认暂停**，用户显式开启后才开始记录。用户显式开启即同时授权「下次启动恢复」（`capture.resume_on_start=1`）：重启后延迟 3s 自动恢复，期间有可见提示且可取消；显式暂停则撤销该授权。无授权时每次启动仍为暂停（M1b，decisions D13）。**M2 起暂停同时停止归纳与出云**：在途请求 abort、结果丢弃，恢复后按游标续跑（D18）。**暂停时即使 settings 写库失败也必须停止采集**（写库失败只影响「下次启动授权」），失败要在界面提示「授权未保存」，不得静默保持采集（F01，2026-10-23）。
- 原始数据（截图/OCR/事件/图谱/归纳）永不离开本机；只有「理解」可脱敏后出云。
- 本项目**默认无遥测、无第三方分析 SDK**。

> **边界化（2026-10-28，D49）**：下面这些规则只在**数据离开设备**时生效。核心载荷组装在 `src/chain/agent/payload.ts`，不 import 脱敏实现；远端供应商由组合根注入 `createCloudAskOutbound()`（`understand/cloud/ask-outbound.ts`），本机模型 / 测试用 `createLocalAskOutbound()` 直通。安全规则坏了 / 还没配好，不得阻断本地检索与工具循环。实现与不变量见 `cloud-boundary.md`。

## 凭据

- `DEEPSEEK_API_KEY` 等用 `.env` / 环境变量；示例配置可提交，真实配置不提交。
- M2 多供应商（D21）：供应商配置只存环境变量名（`apiKeyEnv`），密钥值只从 `process.env` 或 `userData/.env` 读取；密钥、token 不进 settings 表、代码、日志、提交、命令参数、截图。
- **设置界面直接填写密钥（D26，2026-10-23）**：主进程把输入写入 `userData/.env` 的 `apiKeyEnv` 行（原子替换、保留其它行与注释、权限尽力 0600），渲染进程只拿「已配置 / 未配置 / 来源」，值永不回显；settings 写入通道出现 apiKey 类字段仍整单拒绝；同名环境变量优先，UI 如实提示。密钥只经独立通道 `graph:provider:key`（`providerId` + 一次性输入），主进程按已保存供应商反查变量名，不接受渲染进程指定任意变量名。

## 三层脱敏墙（出云唯一出口）

1. **正则层**：AK/SK、JWT/Bearer、配置/JSON 凭据赋值（`api_key: …`、`{"api_key":"…"}` 等带引号形态）、手机号、身份证、银行卡、邮箱、IP、URL query 参数
2. **结构层**：黑名单进程（密码管理器/网银/隐私窗口）只记元数据，且**在截图前判断**（不落 PNG）；检测到密码输入框 → 整帧丢弃
3. **策略层**：命中记 `sensitive=1`，节点显示「内容已保护」占位
4. **出云剥离（M2 起，D19）**：送云端前由边界策略处理——核心 `src/chain/agent/payload.ts` 只做协议组装，云端策略 `src/understand/cloud/ask-outbound.ts` 调同一个 `redactSensitive()`：`sensitive=1` 事件的命中片段替换为 `[已脱敏]` 后再二次扫描；仍命中（含密码类规则）的整条不出云，本地生成「内容已保护」占位节点。业务代码禁止直接请求 LLM（唯一出口原则）。旧 `redact.ts` 的同名导出仅做兼容，新代码不再 import。

- 所有送云端的文本（app / 窗口标题 / OCR 摘要）必须经过**同一个**脱敏函数；禁止业务代码直接 fetch LLM（客户端只接受边界端口产出的载荷）。
- **核心与安全的边界**：本地检索 / 存储 / 工具循环 / 渲染不 import `understand/cloud/redact`，不直接调用 `redactSensitive`；只有边界端口（`AskOutbound` 等）接策略。新增出云调用必须走端口；本机 / 测试可注入直通策略，不得把安全规则当核心验收前置。
- **适用范围（按三条数据边界分别规定，不按「是否离开采集进程」笼统划分）**：

| 边界 | 定义 | 允许的数据形态 |
| - | - | - |
| ① 本机进程间 IPC | 采集进程 ↔ OCR/归纳 worker ↔ renderer，不落盘、不出网 | 允许原始形态（截图位图、OCR 原文）——处理必需；但任何一侧都不得把原文写进日志 |
| ② 写入本地持久化 | SQLite、`userData/shots/`、`userData/logs/` 等本机文件 | 截图默认不存（立项决策）；OCR 处理期间经受控 `userData/tmp/frame-<ts>.png` 短暂落盘（文件桥必需），处理完立即删除，启动时清理崩溃残留（F06，见下）；OCR 文本可原文入库，敏感命中必须标 `sensitive=1`（M1a 方案 §4.2；若拍板改为本地剥离，同步更新本表）；日志只记元数据，永不落 OCR 原文/页面内容/剪贴板文本 |
| ③ 离开设备（出云） | 任何网络传输（M2 起的 LLM 供应商，D21） | **三层墙强制生效的唯一边界**：必须过同一个脱敏函数，命中即剥离/丢弃 |

- 剪贴板/URL 意图信号（M4 起）适用同样三条边界：命中敏感规则的内容不触发提示、不入库、不入日志、不留查询文本。
- 新增敏感规则 = 新增 golden 用例（见 testing.md）。

## 出网

- 仅 DeepSeek（脱敏后）；新增任何外部请求先报备并说明数据内容。M2 起出网对象由供应商配置决定（预设 DeepSeek，可加自定义 OpenAI 兼容供应商，D21）；新增供应商视同新增外部请求，先报备。
- **真实出云需一次性确认（D24，2026-10-23）**：`graph.outbound_consent=1` 之前，自动归纳不启动、手动「立即归纳」也零请求（返回 `consent` 跳过）；确认入口必须在图谱窗口明示「会把脱敏后的标题 / OCR 摘要 / 信息链段内文本发往供应商」（v0.8：信息链双链 / 标签复用同一道门；段正文先按行去重、上限 6000 字，仍过同一脱敏函数）；设置撤销后立即停调度，信息链抽取也跟着停（只留本地向量）。确认门不替代 D18：采集暂停时无论是否确认都零出网。
- **供应商 URL 策略（D21）**：只允许 https；本机网关（`localhost` / `127.0.0.1` / `::1`）允许 http；拒绝 URL 内凭据、query、fragment；携带 API key 的请求禁止跟随重定向（`redirect: 'error'`），避免 Authorization 头被 302 带到别处。
- 出网数据最小化：只发必要字段。
- **图谱 IPC 边界**：`graph:*` 只接受图谱窗口**主 frame**（`event.sender.id` + `event.senderFrame === mainFrame`），iframe / 其它窗口一律拒绝；`graph-preload` 只暴露查询 / 状态 / 立即归纳 / 确认门 / 设置读写 / 供应商模型拉取 / 密钥写入 / 打开时间线，不暴露任意 SQL、文件路径或已保存的密钥；设置读写里出现的 apiKey 类字段整单拒绝（密钥只走 env / `.env`，D21/D26）。
- **获取模型（D26）**：用户点击「获取模型」才向当前填写的供应商发 `GET {baseUrl}/models`（Bearer + `redirect: 'error'` + 10s 超时 + 响应体上限）；只携带密钥本身，不发送任何采集内容；错误消息不包含密钥、URL 凭据或响应正文，日志只记「获取失败」。

## 破坏性操作

- 删除/覆盖/迁移数据：先确认路径与范围 → 备份（库文件命名 `<库名>.db.bak.<日期>`，库名以 M1 建库定稿为准，暂定 `memory.db`）→ 执行 → 保证可回滚。
- schema 迁移由 `openDatabase()` 自动执行：**文件库 schema 落后时先 checkpoint 再整文件备份**为 `memory.db.bak.<yyyy-MM-dd-HHmmss>`；checkpoint 不完整（checkpointed < log，库被其它连接占用）或备份失败则**中止启动**，不在无备份时改用户库（M2 Phase 0）。
- 用 `.bak` 恢复：先关应用、**删除同目录的 `memory.db-wal` / `memory.db-shm`** 再把备份复制回 `memory.db`；否则残留 WAL 会被重放，备份看起来「没生效」。
- 清空事件/截图/整库前必须得到明确确认。

## 权限与 AV

- 只申请任务所需的最小权限；不关闭校验/沙箱/审批。
- **录屏授权（`getDisplayMedia`）只放行采集窗口自己的主 frame**：`defaultSession` 的 handler 是全局的，仅凭 `pendingSource` 放行等于假设「只有采集窗口会请求录屏」；现在按 `request.frame === webContents.mainFrame`（跨进程 wrapper 按 `processId + routingId` 兜底）判定，其它窗口 / iframe / 非视频请求一律拒绝（F08，2026-10-23）。采集窗口仍使用共享 `defaultSession`，未来可换独立 session/partition 进一步隔离。
- **临时帧受控存储（F06，2026-10-23，拍板选「保留文件桥 + 受控清理」）**：`save_shots=0` 只关闭长期另存，不代表截图从未落盘。文件桥 OCR 期间每帧只写 `userData/tmp/frame-<ts>.png`，处理完立即删除；应用启动时按文件名白名单清理上次崩溃 / 强退残留（`cleanStaleFrames` 只删匹配 `frame-<数字>.png` 的文件，目录内其它文件一律不动）；删除失败计入 `temp_delete_failed` 并 warn，日志只带错误码、不记路径原文。清理现存用户残留仍须先确认范围，不能借修复之名直接删用户数据。
- **M1 不上全局键鼠钩子**（AV 误报风险，见 gotchas.md）。

## 对外

- 自用阶段不分发、不推广、不开源；对外发布（含截图/日志分享）先拿到明确授权并脱敏。
