# 门一 20 题回忆基线（协议 + 模板 + 计分）

> 验收线来源：`docs/memory-orb-design-proposal.md` §3.5（D31）；产品主指标见 `docs/memory-orb-design-guide.md` §8.2。
> 状态（2026-10-25）：**协议、题集模板、计分脚本已备；题目待拍板人凭真实记忆填写，尚未真机跑**。没跑之前不能声称门一验收通过。

## 0. 一句话

用 20 道真实回忆题，先在「日历 + 图谱」（**不用检索框**）跑出诚实基线，再用门一「问」检索跑同一套题：**首次来源命中率 ≥ 70%、中位耗时 < 30 秒**。

## 1. 验收线（照抄提案，不改口径）

- 题量 20：内容型 8 / 时间型 6 / 来源型 6。
- 首次来源命中率 ≥ 70%。
- 中位耗时 < 30 秒（20 题整体耗时中位数）。
- 题集进入每周回归（每周跑 B 轮即可，A 轮只在需要对照时跑）。

## 2. 三种题型

| 题型 | 问法 | 例子（示例，不是真实题目） |
| - | - | - |
| 内容型 | 我记得看过关于某件事的东西，它在哪 / 叫什么 | 「上周看的那篇讲本地向量检索的文章」 |
| 时间型 | 某天 / 某时段我在忙什么 | 「周二上午我主要在忙哪件事」 |
| 来源型 | 这件事是在哪个应用 / 窗口里看到的 | 「那份 PDF 是从哪个应用里打开的」 |

## 3. 出题规则（决定这次测的是检索，还是记忆力）

1. **题干不许泄露答案**：不出现 app 名、窗口标题、文件名、URL 片段，日期最多精确到「天」（不写「上午 10 点」）。
2. **每题必须有一个可核查的预期答案**：`app` / `title` / `day` / `snippet` 至少填一个，且真实存在于本地库里。填好后由助手用**只读**连接核对「这条证据存在」，核对时**不把位置告诉答题人**（防止出题阶段就被污染）。
3. **题材取最近 5–7 天真实使用**（当前库覆盖 2026-10-21 ~ 10-25；采集需已正常运行、有事件落库）。
4. **20 题都要有答案**：允许「系统说不知道」是产品原则，但不是一道题；找不到只记未命中。
5. **题目原文属个人内容**：只留在 `.tmp/`（gitignore），不进仓库；仓库只记汇总数字。
6. 出题完成后**不要再打开检索框看答案位置**——那等于提前做了一遍题。

## 4. 两轮怎么跑

### A 轮：诚实基线（日历 + 图谱）

- 打开图谱全局页（球 → 图谱，或 `Alt+Space`）。
- **只用**日历挑日 → 图谱上找主题 / 时刻 → 点开侧栏证据。
- **不碰顶栏检索框**（就当它不存在）；可以缩放、切换「只看主题」、用时间筛选调暗。

### B 轮：门一检索

- 顶栏检索框（`Ctrl+F` 聚焦）：关键词 + app / 标题 / 时间过滤，点「检索」出时刻卡片，点卡片回到那一刻。
- 允许反复改写查询；但「首次来源命中」只看你**第一次点开的证据**。

### 计时与判定口径

- 念完题干开始计时；**点开第一处证据**停表。
- **首次来源命中**：第一次点开的证据（时刻卡片 / 图谱节点 / 侧栏事件）里就能看到预期答案（app + 标题 / 日期 / OCR 片段对得上）。需要再翻第二处 = 未命中。
- 点错了可以继续找，但该题已记未命中；耗时记到「找到正确证据」为止。
- 放弃上限 **120 秒**：到点仍没找到 = 未命中，耗时记 120（统一口径，不靠事后补记拉低中位）。
- 20 题一次跑完，中途不换方法、不中场看答案位置。
- A / B 两轮间隔 **≥ 24 小时**，且 A 轮结束后不记录位置线索。同一套题有记忆效应，报告里要标注这个局限（最理想是另备一套等价的 20 题做 B 轮，成本更高，暂不做）。
- 跑前确认前台**没有全屏应用**（`SHQueryUserNotificationState=2` 时窗口置顶 / 聚焦会异常，见 `docs/agent/gotchas.md`）。

## 5. 记录与计分

```powershell
# 1) 生成 20 题空模板（题型配比已按 8 / 6 / 6 排好）
npm run recall-baseline -- --template --out .tmp/recall-baseline.json

# 2) 填完两轮后出报告（校验不过会逐条指出问题，退出码 1）
npm run recall-baseline -- .tmp/recall-baseline.json

# 3) 要机器可读的汇总
npm run recall-baseline -- .tmp/recall-baseline.json --json
```

每题字段：

| 字段 | 含义 |
| - | - |
| `id` | 1–20 |
| `type` | `content` / `time` / `source` |
| `question` | 题干（不含答案线索） |
| `clue` | 我记得的线索（可选，写给自己） |
| `expected` | `app` / `title` / `day`（YYYY-MM-DD）/ `snippet` 至少一个 |
| `attempts.A` | `{ hit, seconds, first_hit?, note? }` |
| `attempts.B` | 同上 |

计分口径（`scripts/recall-baseline.mts`，有单测钉住）：

- 命中率 = 命中题数 ÷ 20（题型分组同样按该题型的题数作分母）。
- 中位耗时 = 20 题耗时的中位数（偶数个取中间两个平均）；未命中按 120 秒计入。
- 达标 = 命中率 ≥ 70% **且** 中位耗时 < 30 秒（30.0 秒不算过）。
- **验收看 B 轮**；A 轮只作基线对照（报告里给差值）。

## 6. 未命中怎么归因（复盘用）

| 归因 | 含义 |
| - | - |
| 没索引 / 没读到 | OCR 没抓到、该窗口没采到（采集层问题） |
| 找不到入口 | 不知道去哪找、界面没提示（交互问题） |
| 记忆偏差 | 日期 / 应用记错，证据其实在（记忆不是检索的错） |
| 工具慢 | 搜索慢、画布卡（性能问题） |
| 证据不存在 | 采集没覆盖（这道题应重出，不计入正式题集） |

## 8. 与其它验收的关系

- 指导方案**阶段 B（连续一周真实使用验收）**复用同一套记录习惯：每天记真实回忆任务，周末汇总（`docs/memory-orb-design-guide.md` §9）。
- 架构断言（自动化，已有）：归纳全停时检索照常工作——`tests/unit/search.test.ts`「只读 L0：完全没有 moments / nodes / edges 时检索照常」，不靠人工跑。
- 每周回归只跑 B 轮；连续两周命中率掉到 70% 以下，按「没索引 / 没读到」→「找不到入口」的顺序排查。
