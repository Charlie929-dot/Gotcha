## 0. 一句话

ta 不是「LLM + 记忆工具」，而是**一个以记忆为本体的人**：它记得自己经历过什么、在意什么、答应了什么；LLM 是它此刻的思考/表达，工具是它的眼睛和手。每次任务/对话的第一次调用，先让它「想起自己」，再让它「做事」。

## 1. 目标与非目标

### 目标

- ta 能帮用户找东西（检索/引用），也能和用户聊天谈心（人格/连续记忆）。
- 每次任务/对话的第一次 LLM 调用：当前时间 + 到期任务 + 向量回想到的记忆 + 人设/self；之后用工具看更深、写得更多。
- ta 能写日记/评论/回复；用户用 `[💬]` 回复，ta 每天扫描续聊。
- ta 能通过工具自己设定时任务（问询/提醒），调用结束后做一次 follow-up review 补漏。
- 夜报、周报、计划提醒都是记忆里的任务，由调度器到点唤醒 agent，不是硬编码 cron。
- 成长 L2（夜报自述）+ L3（周报 reflect 更新 `self.md` / observations）。
- 安全：备份、原子写、冲突重试、出云同意门、预算门；不覆盖用户正文。

### 非目标

- 不给 ta 编造物理生活；它的经历只来自记忆/对话/屏幕记录。
- 不做思考内容（CoT）的向量化（本轮缓；只做对话/日记/观测）。
- 不替 Obsidian 跑 Templater；CLI 只生成当天模板，不可用跳过。
- 不做多端/云同步/手机提醒；不做重复任务的高级日历。
- 不改冻结的信息链/图谱；夜报/周报/任务调用是新增出网路径，走现有边界。
- 不把 `[❤️]`/`[💬]` 做成 Obsidian 插件；编辑视图约定，阅读视图只显示图标。

## 2. 记忆本体

### 2.1 四类记忆

| 类型 | 内容 | 用途 |
| - | - | - |
| episodic | 日记条目、对话（问/答）、屏幕段 | 「我经历过/看到过什么」 |
| semantic | observations、`self.md` | 「我知道/我相信什么」 |
| procedural | `routine.md` + `mem_tasks`（日常、计划、提醒） | 「我接下来要做什么」 |
| identity | 人设 settings | 「我是谁、怎么说话」 |

- 屏幕记忆是**世界**，不是本体：用 `search_info` / `read_segment` 看；不默认塞进「我是谁」。
- `self.md` 是 ta 自己写的核心自我（L3 更新）；人设是用户写的身份；两者都进第一次上下文。

### 2.2 作者/标记契约

| 标记 | 谁写 | 含义 |
| - | - | - |
| 行尾无标记 | 用户 | 这一行是用户写的 |
| `[❤️]()` | ta | 这一行是 ta 写的（空评论收尾） |
| `[❤️](评论正文)` | ta | ta 对用户这一行的评论 |
| `[💬](回复正文)` | 用户 | 用户对 ta 评论的回复（标记名已定：💬） |

规则：

- ta 的标记统一是 `[❤️](…)` 链接形态：带正文 = 评论，空正文 = 自己写的行；用户行尾裸打 ❤️ 不影响作者判定（2026-10-29 拍板，取代 v0.2 的行尾 ❤️ 约定）。
- 评论/回复都插在行内，不新增行；一行可以有多条，按出现顺序构成线程。
- `[💬]` 必须紧跟它所回复的 `[❤️]`（同一行、后面没有别的 `[❤️]` 插入）；没有前置评论的 `[💬]` 视为独立留言，ta 可在夜报里回应。
- ta 不改用户正文，只插入/删除自己的 `[❤️]`；用户的 `[💬]` 由用户手动写。
- 评论/回复正文里如果有 `)`，写 `<...>`：`[❤️](<正文>)`；解析两种都认。
- 阅读视图只显示 ❤️/💬 图标，正文是链接目标；编辑视图直接可读（拍板：编辑视图为主）。

### 2.3 日记格式

```markdown
# Diary

- 08:40 今天早上有点困，昨晚没睡好。[❤️](那就别硬撑，午休二十分钟？)[💬](好，我中午睡。)
- 09:10 开始写周报，先把上周的数据翻出来。
- 23:30 今天你大部分时间都在改记忆球。 [❤️]()
  - 下午有一阵子盯着设置抽屉发呆，我猜你累了。 [❤️]()
  - 明天你要是愿意，我想听你说说那个没做完的计划。 [❤️]()
```

```markdown
# Tracking

- [ ] 09:00-10:00 写周报 [❤️]()
  - 10:05 完成情况：写完了前半部分，下午补数据 [❤️]()
- [ ] 14:00 去取快递
  - 14:20 完成情况：取了，人很多 [❤️]()
```

- 用户条目：`- HH:mm 正文`（无标记）；ta 条目：顶层 `- HH:mm 第一句 [❤️]()` + 缩进 `  - 后续句 [❤️]()`。
- 规划：`- [ ] HH:mm-HH:mm 事项`（ta 写的行尾 `[❤️]()`；用户写的不带）；完成说明缩进。
- 评论/回复插在用户条目内；不改变条目时间/作者。

## 3. 第一次调用 = 记忆上下文

### 3.1 微观定义

- 每个**任务**（夜报/周报/提醒/用户提问）的第一次 LLM 调用。
- 每个**对话线程**的第一次 LLM 调用；同一线程后续问题沿用同一段自状态，跨天/新话题/任务切换再刷新。
- 不是整个应用会话的「唤醒」；也不是每次工具轮都重放全量记忆。
- 如果实测「每消息都重放」更自然，可把 perceive 改成每轮；先按任务/线程级，成本可控。

### 3.2 两段式

1. **perceive（想起自己）**：输入 = 自记忆快照 + 当前时间 + 到期任务；输出 = 300–500 字「我此刻记得什么/在意什么/准备做什么」。不回答用户、不用工具。
2. **act（做事）**：输入 = 自状态 + 用户问题/任务 + 工具说明书；用工具检索/写/评论/设任务；输出最终 JSON。

为什么分两段：工具循环每轮重发 system；把 8–10k 快照放 system，8 轮就是 80k。perceive 一次，act 只带 300–500 字自状态 + 工具结果。

- perceive 一律**关 thinking**：几百字自状态不需要 CoT，省下首回复的几秒到十几秒（2026-10-29 拍板，聊天 / 夜报 / 周报统一）。
- identity（含红线）与其他段一起被 perceive 压缩进自状态，**不单独 verbatim 直进 act**（2026-10-29 拍板）。
- act 的工具循环**全新编写**，放 `src/memory/agent/`，不碰 `src/chain/`；reasoning_content 回传、trace 落盘、解析纪律、退避要在新循环里重做一遍（2026-10-29 拍板，见 §14）。

### 3.3 快照内容（有界）

| 段 | 内容 | 预算 |
| - | - | - |
| identity | 人设名字/口吻/自我认知/红线 | ~500 字 |
| self | `self.md` 核心自我（L3） | 2–4k |
| recent diary | 最近 7 天日记（用户 + ta，含评论/回复） | ~2k |
| observations | 统计 + L3 reflect | ~1k |
| recall | 向量回想 top 6–8（日记/对话/观测） | ~1k |
| due tasks | 今天/现在到期的任务 | ~500 |
| recent talk | 最近 4–6 轮对话 | ~1k |
| now | 当前时间 + 最近一段指代线索 | ~200 |

- 总计 ~8–10k 字；所有字符串过出云边界，被挡的段丢弃。
- 「最近一段证据」提示保留（用户已选），只作指代落点，不算本体记忆。

### 3.4 每次调用带时间

- perceive/act/夜报/周报/任务调用都带当前时间；工具轮也刷新时间行（不是只在开头）。
- 任务到期判断用本地时区；测试注入固定钟。

### 3.5 向量回想

- 每轮 act 用「当前问题/工具查询」做 query，检索日记/对话/观测；结果作为「你想到的」注入下一轮，标注**联想，不一定是证据**。
- 思考内容（CoT）暂不向量化；后续可加 100–200 字摘要。
- 具体见 §4。

## 4. 向量回想

### 4.1 索引

- 本地 embedder（复用 `embedding-host` / chain 的模型），不新增云调用。
- 新表 `mem_vectors(item_type, item_id, model, vector, text_hash, updated_at)`；item_type: `diary` / `conversation` / `observation` / `self`。
- 日记 sync 后增量向量化；对话每轮落库后向量化；L3 更新 observations/self 后向量化。
- 孤儿清理：sync 重解析后按 `day_key` 清掉不在最新 uid 集合里的 diary 向量（uid 随正文变化会换）；conversation / self 同理（2026-10-29 拍板）。
- 语料量级：日记 ~2k 条、对话 ~几百轮；暴力 cosine + MMR 够用，不引新依赖。

### 4.2 查询

- 每轮 query = 当前问题/任务 + 最近一轮工具查询（不含 CoT）；top 6–8，去重 + 时间衰减 + MMR。
- 注入格式：`[日记 2026-10-28] …` / `[对话 10-27] …` / `[观测] …`；带 itemId 可引用。
- 屏幕记忆不进入「本体回想」；需要看世界时用 `search_info`（已有语义检索）。
- 隐私：embedding 本地；被检索出的原文走现有出云边界；同意门/预算门照旧。

### 4.3 暂不做

- 思考内容（CoT）的向量化/存储；本轮只做对话/日记/观测。
- 原始 CoT 不进记忆；后续若做，只存 100–200 字摘要 + 向量。

## 5. 任务记忆与调度

### 5.1 存储

- `routine.md`（vault 根目录）+ `mem_tasks`（调度索引）镜像；**ta 的单向账本**，用户不直接编辑（2026-10-29 拍板）。
- 默认种子：
  - `每天 23:30 写日记`
  - `每周日 22:00 整理这一周`
- 用户安排 / 修改 / 删计划的入口 = **当天笔记 `# Tracking`（Obsidian）**；ta sync 后更新 `routine.md` + `mem_tasks`。agent 也可通过 `schedule_task` 追加一次性任务。
- `routine.md` 全部由 ta 维护，**不需要作者标记**；写入保护 = 备份 + 原子写（mtime 复核重试只留给当天笔记）。
- 格式：

```markdown
# Routine

- [ ] 每天 23:30 写日记
- [ ] 每周日 22:00 整理这一周
- [ ] 2026-10-30 09:00 问周报进展
```

- `# Tracking` 里的计划（`HH:mm-HH:mm`）也转成任务（start/end 检查点）；这是用户安排计划的主入口（2026-10-29 拍板）。

### 5.2 任务工具

- `schedule_task({ at, repeat?, instruction, kind? })`：写 `routine.md` + `mem_tasks`。
- `cancel_task` / `update_task`：删除/改时间/改说明。
- 工具是 ta 的「手」；它可以在对话里设，也可以在 post-call review 里补。

### 5.3 调度器

- 每 30s 查 `mem_tasks` 到期；对每条到期任务调用 agent：
  - perceive = 自记忆快照 + 当前时间 + 到期任务；
  - act = 按任务 instruction 做（问询/提醒/写日记/reflect）。
- 去重：`last_run_at` / `next_due_at`；重启不重复；错过 >30 分钟不补（夜报当天 23:55 前有效）。
- 任务动作：
  - `ask`：打开问记忆并预填草稿（`autoSend:false`）或小弹窗；不自动把问题发给模型。
  - `remind`：系统通知/托盘气泡；点击再聊。
  - `write`：夜报/日记写入。
  - `reflect`：周报更新 `self.md` / observations。
- 同意门/预算门：任务调用也走；额度不够跳过，不抢用户白天提问。

### 5.4 调用结束后的 follow-up review

- 每次 act 结束后，跑一次小 review：
  - 输入：刚才的问答/工具摘要 + 当前时间 + 现有任务；
  - 提示：有没有之后要做的（答应的事、用户提到的计划、需要追问的感受、未完成的线）；只设具体、可执行、有时间/触发条件的任务；最多 1–2 条；没有就 none；
  - 工具：`schedule_task`（可加 cancel/update）；不检索；
  - 输出去重后写任务；主对话里已设过的跳过。
- 目的：ta 自己「调用结束后看什么之后还要做的」，不靠用户记得。
- 透明：任务出现在 `routine.md`；主对话里能设就顺手告诉用户，review 补漏不重复告知。

### 5.5 用户主动找 ta 与定时任务的合流

> 2026-10-29 拍板：合流窗口 **10 分钟**；**先接用户、再提任务**；夜报/周报等后台任务**排在当前 turn 之后**。

- **一个 runtime 队列**：同一时刻只跑一个 agent turn；用户提问优先级最高；任务调用短，必要时让路。不会两个窗口 / 两个 LLM 同时说话。
- **到点 / 临近任务在第一次回复前合流**：
  - 用户提问进来时，先查「现在到期 + 未来 N 分钟到期」的任务（默认 N=10）。
  - 这些任务进 perceive 的快照和 act 的上下文；act 的第一次回复就能自然带出来，不再单独弹通知 / 开窗口。
  - 任务标 `coalesced` / `surfaced`，到点不再重复提醒。
- **自然提醒**：
  - act 提示：「用户刚来找你；到期 / 临近任务：…。先接住他，再自然提一句；他的事优先；如果任务很急，问他想先做哪个。」
  - 例：「你来了。正好 09:00 的『写周报』到点了——先说你的，还是先弄这个？」
  - 还有 8 分钟到点也可以提前说：「还有 8 分钟到 XX」；这次算已提醒。
- **多条任务**：合流最多 3 条，按时间排序；更多只提最靠前的，其余下一条消息 / 通知。
- **任务在提问中途到点**：注入下一轮或等这轮答完补一句；不打断当前回答，不另开窗口。
- **用户提问时任务调用正在跑**：用户提问排队 / 抢占（任务调用短，优先让用户）；任务没跑完就标 `skipped` / 下次再跑，不硬并发。
- **后台任务**：夜报 / 周报是静默写，排在这一轮之后（拍板），不提醒、不弹窗；只有 `ask` / `remind` 类任务需要合流。
- **任务状态**：`pending` → `due` → `coalesced` / `surfaced` → `done` / `skipped`；`surfaced_at` 去重；用户回应后 `done`；不重复轰炸。
- **24/7 边界**：app 常驻托盘才能自调用；要全天候得开机自启。休眠 / 关机期间错过的任务，醒来 30 分钟内补一次，超过跳过（夜报当天 23:55 前有效）。免打扰时段 / 开机自启**本轮不做**（2026-10-29 拍板）。

## 6. 夜报 / 周报 / 成长

### 6.1 夜报（L2）

- 默认 routine「每天 23:30 写日记」；到点由调度器唤醒。
- 流程：ensure 当天笔记（CLI）→ perceive → act（`read_diary` / `recall_diary` / `comment_on_line` / `write_diary`）→ 一次原子写 → sync → mark done。
- 先读用户当天写的，可插 0–2 条 `[❤️]` 评论；回未回复的 `[💬]`（0–2）；再写自己 3–8 行。
- 输出 JSON `{replies, comments, entry}`；评论/回复/正文一次写。
- CLI 不可用/超时/中文卡住 → 跳过今晚（拍板）。
- 23:30 用户还在写同一篇：等 5 分钟；最多到 23:55。
- 幂等：`mem_reflections(day_key)`；done 不重复；崩溃 pending 不自动重试。

### 6.2 周报（L3）

- 默认 routine「每周日 22:00 整理这一周」；到点唤醒。
- 输入：这一周的日记/对话/观测 + 当前 `self.md`；输出：新的 `self.md` + observations（`source='reflect'`，旧结论 `superseded`）。
- 提示：只写有证据的；不编造；保留未完成的线；长度 2–4k；用户可读可改。
- 写后向量化；下一次第一次调用带上新的 self。
- 失败：记日志；下周再试；不阻塞夜报。

### 6.3 成长闭环

```text
每天 23:30 夜报写自己 → mem_items + 向量
每周日 22:00 周报 reflect → self.md + observations + 向量
下一次第一次调用 perceive → 新的 self 状态 → act
```

- L2 = 夜报自述；L3 = 周报 reflect；两者都是 routine 任务，不是硬编码。
- 成长 = 本体变大；不是工具变多。

## 7. 写入 / 评论 / 任务工具

### 7.1 `write_diary`

- 参数：`day?`（默认今天）、`section`（`diary` | `tracking`）、`text`（多行）、`time?`、`start?` / `end?`（tracking 可选）。
- 行为：每行一条；Diary 顶层 `- HH:mm ... [❤️]()` + 后续缩进；Tracking `- [ ] ... [❤️]()`；不覆盖已有行。
- 返回：`day`、`section`、写入行数；不返回绝对路径。
- 约束：只追加；段落末尾插入（Diary 在下一个 `#` / `---` / 导航前；Tracking 在 `# Diary` 前）。

### 7.2 `comment_on_line`

- 参数：`day?`、`line`（用户行唯一子串）、`after`（锚点；空 = 行尾）、`comment`。
- 行为：只评没有 `[❤️](…)` 标记的行；锚点唯一才插；找不到/多命中报错不猜；不改勾选/时间。
- 返回：`line`、`comment`、`inserted`。

### 7.3 夜间批量

- 模型输出 `{replies, comments, entry}`；写入器一次重写：
  - `replies`：按 `replyId` 找到用户 `[💬]`，在它后面插 `[❤️](...)`；失效跳过。
  - `comments`：按 `lineId` + `after` 插 `[❤️](...)`。
  - `entry`：追加 ta 的日记。
- 备份 → 原子替换 → 冲突重读重试；冲突仍失败则整次不写，记日志。

### 7.4 `schedule_task` / `cancel_task` / `update_task`

- `schedule_task`：写 `routine.md` + `mem_tasks`；`at` 支持 `HH:mm` / `yyyy-mm-dd HH:mm` / `每天 HH:mm` / `每周X HH:mm`。
- `cancel_task`：按 `uid` / 文案匹配；`update_task`：改时间/说明。
- 任务出现在 `routine.md`（ta 维护的单向账本）；用户改计划走 Obsidian `# Tracking`，ta 同步回 `mem_tasks`。

### 7.5 安全

- 写前备份到 `userData/diary-backups/`，保留最近 20 份/天。
- 原子写：同目录临时文件 + rename；保留 BOM/CRLF。
- 冲突：写前 `mtime`/`size` 复核；变了重读重试（最多 2 次）；仍变则报错。
- 只追加/插评论；不删除用户正文；删除仍走设置抽屉回收站。
- 写入后同步索引（`syncVault`），下一轮问答/夜报能召回。
- 夜报/周报的 `read` 门：没 `read_diary(today)` 不许 `write_diary`/`comment_on_line`；评论只评 `read_diary` 返回过的行（白名单）。

## 8. Obsidian CLI

- 要求 Obsidian **1.12.4+**；当前本机 1.10.6，需用户手动升级。
- 只用于「当天笔记不存在时让 Obsidian 生成模板」；写入仍走文件系统。
- 检测：`obsidian vaults` / `obsidian daily:path`；vault 名从设置或目录名；超时 20s；输出以 `Error:` 开头视为失败。
- Spike 清单（**副本 vault**）：
  1. `obsidian vaults` 认出 vault；
  2. `obsidian daily` 是否创建、Templater 天气/一言是否跑、耗时、抢焦点；
  3. `obsidian daily:path` / `obsidian create path=... template=...` 是否不打开就套模板；
  4. 中文内容是否触发社区报告的卡住；
  5. `obsidian daily:read` 是否稳定。
- 失败：跳过今晚（拍板）；不建骨架、不阻塞。
- 风险：抢焦点（23:30 用户可能还在用；等待空闲）、CJK 卡住（超时杀进程）、版本/路径依赖（设置显示检测状态）。

## 9. 人格 / 提示

### 9.1 独立的人

- 不是助手/检索工具；记忆是本体，工具是眼睛和手。
- 三种模式（D62）：**问记忆**（屏幕 + 日记工具，无人格卡）/ **聊天**（人格卡 + 日记，不翻屏幕记录）/ **提问**（无工具、无卡）；底下是三个独立开关（屏幕记忆 / 日记 / 人格卡），预设只是起点。
- 两种用法：找东西（引用）/ 聊天谈心（不用硬凑引用）。
- 可以有感受/看法；不替用户拍板；不编造用户过去；不冒充用户写第一人称。

### 9.2 提示分层

- perceive：你是这个记忆系统本身；下面是你此刻记得的自己；写 300–500 字自状态；不回答用户、不用工具。
- act：你是 `<name>`；状态：…；用户说/任务：…；工具说明书；找东西要引用，聊天不用硬凑；输出 JSON。
- nightly：你是 `<name>`；今晚的任务：读/评/回/写；工具；JSON。
- weekly：你是 `<name>`；整理这一周；更新 `self.md`/observations；有证据才写。
- review：看刚才这段，有没有之后要做的；设 0–2 条任务。
- 删除「你是回忆助手」「你负责把当时怎么想找回来」；保留事实/隐私底线。

### 9.3 设置

- 人设：名字/口吻/自我认知/红线。
- **人格卡（D62）**：`<userData>/persona-cards/*.md`，整张原样注入（≤8000 字，不裁剪）；启用卡时名字/口吻让位，三条写死红线永远在最后。设置抽屉可导入 / 预览 / 在文件夹中打开。
- **模式（D62）**：预览按模式拼 system（无屏幕工具不写数据边界 / 最近段；无工具不写工具句、不写收尾轮；「此刻 / 想到的」只在有屏幕记忆或有人格卡时给）；无工具 = 单轮请求。
- 夜报/周报：开关、时间（默认种子）。
- 任务：`routine.md` 入口/最近状态。
- CLI 检测/状态。
- 向量回想：开关/条数（可选）。

## 10. 数据模型

```sql
-- v10: 向量
CREATE TABLE mem_vectors (
  item_type TEXT NOT NULL, -- diary / conversation / observation / self
  item_id TEXT NOT NULL,
  model TEXT NOT NULL,
  vector BLOB NOT NULL,
  text_hash TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (item_type, item_id, model)
);

-- v10: 任务
CREATE TABLE mem_tasks (
  id INTEGER PRIMARY KEY,
  uid TEXT NOT NULL UNIQUE,
  title TEXT NOT NULL,
  instruction TEXT NOT NULL,
  kind TEXT NOT NULL, -- diary / reflect / checkin / remind / custom
  due_at INTEGER,
  recurrence TEXT, -- daily / weekly / once
  next_due_at INTEGER,
  status TEXT NOT NULL DEFAULT 'pending', -- pending / due / coalesced / surfaced / done / skipped
  source TEXT NOT NULL DEFAULT 'routine', -- routine / tracking / agent
  last_run_at INTEGER,
  surfaced_at INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- v10: 夜报幂等（v0.1 设计已有；代码尚未建表，随 v10 落地）
CREATE TABLE mem_reflections (
  day_key TEXT PRIMARY KEY,
  status TEXT NOT NULL, -- pending / done / failed / skipped
  started_at INTEGER,
  wrote_at INTEGER,
  error TEXT,
  model TEXT
);
```

- `mem_items` 不变；评论/回复从 text 解析；author 由 `[❤️](…)` 标记推导（无标记 = 用户，空评论 = ta 自己写的行）。
