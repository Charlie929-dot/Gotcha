# 记忆球指导方案：从数字经历到可信记忆

## 0. 一句话与北极星

**记忆球是一个安静陪在电脑边缘的私人自传体记忆：平时保留数字经历的来龙去脉，需要时沿着线索，把过去轻轻送回用户手边。**

它不是屏幕录像机、手动知识库或主动通知中心。它保存的不只是「看过什么」，还包括「为什么相遇、信息如何流动、后来产生了什么结果」。

**北极星：不是把图画出来，而是让记忆找回来、让事情续上去。**

判断任何设计与优化，先问三个问题：

1. 是否让真实回忆任务更快、更准地完成？
2. 是否保留了回到原始证据的路径？
3. 是否让用户更愿意长期、安心地运行？

若只增加图谱复杂度、节点数量或 AI 文案，而不能改善以上任一项，就不进入当前主线。

## 1. 产品图景：经历如何成为记忆

```text
经历发生
  屏幕内容、窗口、时间、剪贴板与导航等可观测信号
    ↓
留下证据
  原始事件可核查；敏感内容受保护；用户随时可暂停
    ↓
形成记忆
  时刻是可重建投影；窗口与双链组织内容；日/周/月/年提供不同抽象层级
    ↓
建立关系
  双链出处、窗口成员、行为转移分轨表达，不混成一种“相关”
    ↓
悄然重逢
  找回过去、续上任务、理解解决过程；高把握时才弱提示
```

三个核心价值：

- **找回**：这段内容我以前在哪见过？
- **续上**：上次做到哪一步，接下来是什么？
- **理解**：当时怎样从问题走到结果，哪些经历真正相关？

情感价值来自真实经历的重新相遇，不来自 AI 为过去编造心理独白。

## 2. 不可动摇的设计原则

### 2.1 原始经历是唯一事实源

- L0 原始事件不因窗口、双链、摘要或行为关系而被改写。
- 所有上层结论都必须能下钻回原始事件；缺失来源要显式暴露，不静默补齐。
- AI 可以命名、归纳、确认模糊归属和生成提示，但不能把推测写成事实。

### 2.2 派生层必须可重建、可纠错

- `moments` 是带生成规则的投影，不是天然、不可变的事实单元。
- 窗口、双链、向量、边、位置、分层摘要都属于派生数据。
- 生成规则要可版本化；调整切分、模型或阈值后，应能重建派生层而不损坏 L0。
- 自动合并、归属和用户纠错要保留审计与撤销路径。

### 2.3 允许系统说「不知道」

- 不确定时进入待确认、保持候选，不强行归档、新建双链或连边。
- 自动接受不只看最高分，还要看与第二名的差距、反证和候选歧义。
- 无回显、OCR 漏帧、窗口已关闭等「没有证据」不能被解释成「事情已经发生」。

### 2.4 隐私与可控制是产品本体

- 本地优先；出云只走既定脱敏与授权出口。
- 默认暂停、显式开启、随时可逃；暂停语义覆盖所有新增采集信号。
- 删除以原始事件为根，派生数据可随之失效或重建；备份也要有明确保留边界。
- 暂停不是失信，而是用户拥有控制权的证明。

### 2.5 弱主动，强响应

- 默认沉默，不弹窗、不抢焦点、不用通用建议争夺注意力。
- 只有当前上下文与过去记忆高置信相接时，球才轻微提示。
- 点开返回用户自己的经历与证据，不优先给泛泛的 AI 回答。
- 提示可以忽略；忽略成本必须足够低。

## 3. 统一记忆模型

记忆不再是「一张主题图上的层级」，而是两条线、若干可下钻的层：

| 层 | 回答的问题 | 指导约束 |
| - | - | - |
| 原始观测 / L0 | 当时实际观测到什么？ | 忠实、带时间、带来源；**观测不等于真相**，UIA/OCR 会错 |
| 窗口 | 哪一段前台窗口占用适合一起查看？ | 可重建、可版本化；不把切分口径当自然事实 |
| 双链单元 | 这段内容里出现了什么可复用的东西？ | 必须有原文出处；窗口↔双链多对多；别名可合并、拆分、撤销 |
| 个人记忆 | 这些加起来说明你是谁？ | 只收筛选后的内容 + 来源引用；可更新、可过期、可删除 |
| 行为关系 | 信息从哪里流向哪里？ | 独立存储与展示；不污染信息链，不参与图谱布局 |
| 日/周/月/年 | 拉大尺度后如何理解这段时间？ | 每层可下钻；摘要不能替代原始记忆 |
| 提示与解说 | 过去怎样帮助现在？ | 事实、归纳、推测分层；高把握、可解释、可反馈 |

> **v1.2 修正**：主题（对窗口的语义聚类）不再是图谱层。它是解释，不是观测；不进入信息链图，旧主题图只作 legacy 视图。图谱只表达窗口球与双链球的关系。

### 3.1 「窗口」的特别约束

当前「同 app + 同标题 + 相邻 ≤90s + 同本地日」适合作为工程切分起点，但存在长任务切碎、同标题异题、跨窗口任务被分割等天然误差。

因此：

- 窗口切分规则不能反向修改原始事件。
- 窗口重建要有明确版本与迁移策略；旧窗口标记 `superseded_by`，不物理删除。
- 需要精确定位的行为关系连接原始事件或事件内文本片段，不绑死 window id。
- 图谱上的窗口是探索入口，不是记忆精度的上限。

### 3.2 双链球与窗口的生命周期

全局图不能只是无限累积的星尘。窗口与双链球应逐步具有生命周期语义：

- 双链球：活跃、沉寂、归档；首次/最近出现、出现次数、跨天跨度；
- 窗口：不删，只被新切分标记 `superseded_by`；历史窗口仍可检索、下钻；
- 一次性双链默认折叠，反复出现的双链优先展示；
- 默认突出活跃与重要的记忆，其余仍可搜索、展开，不因归档而删除。

全局仍是一张图，但记忆应有远近、轻重和沉寂。LOD 同时解决渲染规模与认知负担。

### 3.3 找回的入口

检索与图谱并列为「找回」的一等入口：关键词与结构化过滤（应用、标题、时间窗）直接作用于原始事件层，不依赖事件是否已被归纳；图谱负责探索与定位，检索负责定向回到那一刻。两者同源于 L0，互不为前置——「未归纳」不等于「不可找回」，归纳层整体不可用时检索仍然工作。

个人记忆的 `recall` 是第三条入口：它先判断「什么与你相关」，再把候选与来源引用交给信息链取证据；它不能替代检索与图谱，也不能在没有证据时给答案。

### 3.4 双链球的存在性

双链球不是「主题的另一种叫法」。它必须满足：

- 在某个窗口的 OCR/UIA 文本里**实际出现**，并留下 `event_id + 原文片段`；
- 没有出处的候选只能停留在待确认队列，不能进主图；
- 合并/拆分/改名有审计、可撤销；精确别名才自动复用，模糊相似只提示。

这条约束把「语义相似」从信息链里请了出去：相似可以做候选提示，不能做成员事实。

## 4. 图谱设计指导

### 4.1 当前正途

以下方向继续保留：

- 单一全局图，时间用于筛选与调暗，不按日割裂记忆。
- **窗口球 + 双链球**两类节点；窗口↔双链的成员边是唯一常驻边。
- 事件与截图留在窗口内部，通过侧栏下钻；事件不上主图，不承担归纳意义。
- 双链必须由原文出处连接；语义聚类不生成成员关系，主题相似边不进入新图。
- 双链合并有审计、可撤销；时间筛选不改变底层数据。
- 行为转移若加入画布，使用独立覆盖层，不参与信息链布局。

### 4.2 双链提取：宁可少提，不可造球

双链不是「最高分归属」，而是「原文里到底有没有」：

```text
本地高精度模式（引号/路径/URL/代码标识/报错码）
+ LLM 候选（只提议，必须带 quote）
+ 原文校验（quote 必须能在窗口文本里找到）
+ 精确别名复用 / 新建 provisional
```

处理顺序：

1. 有原文出处、模式确定：自动建球或复用。
2. 候选接近、别名疑似重复：进确认队列，不自动合并。
3. 找不到出处、证据不足：丢弃或留待确认；不为追求覆盖率强行造球。

阈值必须按用途分别标定：自动建球、别名合并、候选提示不能共用一套分数解释。更换 OCR/UIA 口径、模型或提取器版本后重新标定。

### 4.3 双链合并：工程安全之外，还要验证语义正确

合并除了验证「窗口不丢、可以回滚」，还要验证「确实指同一个东西」。

重点防范：

- A≈B、B≈C 形成传递式链式合并；
- 大分量合并后双链不断扩张、吃掉近义词；
- 合并审计只记录操作，却没有抽样检查语义准确率；
- 为降低节点数而把「降低双链数」本身当成功指标。

精确别名可以自动复用；模糊相似只提示，合并要人确认。质心/向量适合发现近重复，但不必然是「同一个双链」的判据；保留原文表面形式比均值更可靠。

## 5. 行为转移：后续增强，不阻塞当前 M2

### 5.1 目标与边界

行为转移要保存的是「经历的形状」：

```text
报错 → 搜索 → 阅读资料 → 修改配置 → 出现后续结果
```

它补充语义图谱无法表达的信息流向，但不证明人脑中的真实意图，也不把相似性直接当因果。

实施顺序上，先让 M2 在线记忆闭环和真实找回成立，再把行为转移作为 M4 及后续的精度增强。第一版弱提示不依赖完整转移系统。

### 5.2 三层对象必须分开

1. **原始信号**：`clipboard_changed`、焦点变化、导航、文本变化；只陈述观测事实。
2. **转移候选**：由规则产生的假设，含证据、分数、检测器版本与候选组。
3. **已接受关系**：自动接受或用户确认后的投影，可被拒绝、撤销与重建。

概念契约：

```text
transition_candidate {
  src_ref, dst_ref,          // 原始事件或文本片段，而非仅限 moment
  kind,
  payload_ref,               // 避免在关系表重复保存正文
  score,
  state,                     // candidate / accepted / rejected / expired
  decision_by,               // rule / user；若未来新增其他来源须另拍板
  evidence,
  detector_version
}
```

### 5.3 关系类型与置信边界

| 类型 | 含义 | 指导口径 |
| - | - | - |
| T1 | 跨窗口复制后出现 | 明文一致且有时序、来源与新颖性证据时才可高置信 |
| T1b | 复制后进入掩码/无回显区域 | 无回显不是粘贴证据；只作低置信候选，不自动成边 |
| T2 | 源文本成为后续查询 | 精确词形优先，语义改写辅助；区分相关与真实来源 |
| T3 | 查询后打开结果 | 优先要求导航与页面变化，不能只凭搜索页重复查询词 |
| T4 | 同窗口复制后使用 | 连接事件/片段；不能要求存在两个 moment |
| typing/editing | 编辑或输入活动显著性 | 只用于提示声明目标或调整采样，不直接成边 |

### 5.4 转移判断的四个新约束

- **来源可用**：源内容在行为发生前可见或可获得。
- **目标新颖**：目标此前没有该内容，随后首次出现；避免把已有内容倒推成转移。
- **时序连续**：时间顺序、焦点路径与导航过程不矛盾。
- **来源排他**：存在多个合理来源时保留候选组；第一名优势不足则不自动接受。

每种关系独立设置时间窗、分数与阈值。精确指纹、子串、编辑距离和向量余弦不是天然可比较的同一量纲，不能统一乘一个时间衰减后就自动判真。

### 5.5 用信号改善采集，而不是只改善猜测

2 秒周期可能漏掉快速复制、粘贴、撤销。剪贴板序号和焦点变化可在隐私开关允许时触发补采：

- 剪贴板变化后补采可能的源窗口；
- 焦点变化后补采新窗口；
- 对疑似目标窗口短延迟再采一次，避开刷新动画。

先减少证据缺失，再提高推断复杂度。

### 5.6 用高置信转移校准模糊转移

高置信 T1/T4 可作为本地正样本，明显无关候选与用户拒绝可作为负样本，用于校准 OCR 归一化、最小有效长度、字符/token 匹配和向量阈值。

优先让确定性证据帮助标定本地规则，不默认把模糊关系交给 LLM 判真。

### 5.7 敏感信息与隐私边界

- 敏感剪贴板只做内存内短时匹配；持久化指纹也需单独评估，不能默认视为匿名。
- 非敏感正文与敏感派生数据采用明确的保存、保留和删除策略。
- 对承诺「不入库」的敏感内容，掩码或丢弃必须发生在持久化之前，并覆盖队列、缓存与日志；本地敏感 OCR 的既有口径仍按 D10，更严的新规则另行拍板。
- URL query 本身可能包含密钥与私人内容，采集前需要权限、脱敏和范围设计。
- 暂停时所有新增信号采集与相关出网都遵守既定暂停语义。

### 5.8 更高层价值：解决闭环

比「查过资料」更有价值的是：

```text
问题 → 探索 → 修改 → 可观察的成功结果
```

它可帮助识别哪些资料后来真正有用。但「报错消失」也可能只是窗口关闭，必须结合后续成功标记、同一会话和其他反证；证据不足时只称「可能相关」，不宣称「已经解决」。

## 6. AI 与解说文案的可信边界

AI 输出分三层表达：

| 层 | 可以怎样说 | 示例 |
| - | - | - |
| 事实 | 有直接事件证据 | 「16:20 你查看了该报错，16:32 打开此文档」 |
| 归纳 | 多个事实的保守概括 | 「这段时间主要围绕同一环境问题展开」 |
| 推测 | 明示不确定性且可关闭 | 「这篇资料可能与后续修改有关」 |

禁止把以下推断写成事实：

- 「当时已经解决」，但没有结果证据；
- 「这篇文档促成了修改」，但只有语义相似；
- 「那时你很焦虑/投入/开心」，但没有用户显式记录；
- 「你在思考什么」，仅凭输入、切换或浏览行为。

记忆可以有温度，但不能靠虚构心理活动获得温度。

## 7. 弱提示的最小闭环

第一版主动提示不需要完整行为转移系统：

```text
复制报错或产生明确查询
  → 本地检索历史窗口、双链与原始证据
  → 高把握、非敏感、未超频
  → 球轻微脉冲一次
  → 用户点开：相关时刻 + 原始记录 + 为什么提示
  → 用户反馈：有用 / 无关 / 此类不再提示
```

提示质量优先级：有用率与成功找回高于点击率。点击可能来自好奇，不能单独证明价值。

提示必须解释「为什么出现」，提供低成本关闭方式，并遵守频率、静默时段、敏感内容与暂停规则。

## 8. 验收与长期指标

### 8.1 工程正确不等于产品成立

测试、类型检查、构建、E2E、性能与迁移回滚继续作为提交闸门；它们证明系统按设计运行，不证明设计已经帮助回忆。

### 8.2 产品主指标

| 维度 | 核心问题 | 建议度量 |
| - | - | - |
| 找回 | 能否找到正确过去？ | 真实回忆题成功率、耗时、首次来源命中率 |
| 续上 | 能否还原任务上下文？ | 能否找齐问题、资料、修改与结果证据 |
| 双链建球 | 新内容是否进入正确的球？ | 人工抽样接受率、待确认比例、假球率 |
| 双链合并 | 合并是否指同一个东西？ | 抽样准确率、链式误并、撤销情况 |
| 提示 | 是否值得打扰？ | 有用确认率、提示后找回率、误提示/天 |
| 信任 | 是否愿意长期安心使用？ | 持续启用、暂停后恢复、预期外记录为零 |
| 成本 | 是否无感运行？ | CPU、卡顿、功耗、出云量与模型耗时 |

「连续 30 天不暂停」不作为信任目标；暂停是健康能力。「每周点击 ≥3 次」不作为提示价值的唯一证明。

### 8.3 行为转移的专项验收

- 人工抽查只能估精确率，另需脚本化执行已知操作测召回。
- T1/T4、T1b、T2、T3 分开统计，不混合成一条总准确率。
- 覆盖同窗口、跨窗口、OCR 噪声、短文本、多来源、剪贴板覆盖、无回显和快速撤销。
- 记录误连/天与漏连率；每条接受关系都能回到两个原始事件或片段。
- 用户拒绝是检测器改进样本，不与系统自动 drop 混为一个状态。

## 9. 分阶段路线与出口标准

> v1.2：阶段顺序按 `docs/memory-orb-architecture-v2.md` §9 重排；旧「主题在线归属」阶段由双链信息链接替。产品出口标准不变。

### 阶段 A：信息链内核（架构 v2 P0–P1）

做：数据审计、v7 双链表、本地双链提取 + 原文校验 + 别名/合并审计；先不接 UI。

不做：不因新图而删旧主题数据；不扩大采集面。

出口：真实库副本回填后，抽样窗口的双链条目能回到原文；假球率低于验收线；重跑幂等。

### 阶段 B：新图与连续真实使用（P2–P3）

做：新图谱页（窗口球 + 双链球）在 feature flag 后上线；与旧图并行；连续一周记录真实回忆任务；回填最近 90 天。

出口：不仅测试全绿，还能证明「双链能定位窗口、窗口能下钻证据」；旧图仍可打开；没有数据被删。

### 阶段 C：M3 分层记忆与生命周期

做：日/周/月/年、LOD、双链球活跃/沉寂/归档，保持全链路下钻。

出口：缩小能看到高频双链与聚合，放大能还原窗口与事件；规模增长不导致认知失控。

### 阶段 D：个人记忆最小闭环（P4）

做：独立记忆库、retain/recall、来源引用、删除/导出、反馈。

出口：每条记忆有来源或标 inferred；删窗口后来源显式悬空；个人记忆坏了不影响信息链。

### 阶段 E：Hindsight 评估、弱提示与行为转移（P5–P6 / M4+）

做：Hindsight 本地 spike（不通过就保留内置）；复制/查询触发本地检索；高置信脉冲；事实优先的解说；经单独拍板后再加行为转移。

出口：提示被证明有用且打扰足够低；Hindsight 采用与否有明确证据；无提示时系统仍有完整手动找回价值。

## 10. 明确不做与防止偏航

- 不做密钥管理；不因记录关联而变相保存密钥，也不把哈希指纹天然视为可安全保存的替代品。
- 不让 AI 批量编造语义边、行为因果或过去的心境。
- 不把原始事件全部塞上全局画布。
- 不为追求记忆完整度而无限扩大采集面和隐私面。
- 不把主题数、双链数、边数、脉冲次数、点击量当核心价值。
- 不在当前 M2 尚未在线闭环时插入完整 transitions 系统。
- 不因未来可能有需求而提前建设通用插件平台或复杂因果推理引擎。

## 11. 后续实施前需要单独拍板的事项

1. `moments` 生成版本、重建与旧引用迁移契约。
2. 「待归属」状态及其 UI、回填与统计口径。
3. 双链球与窗口的生命周期字段、默认展示和归档语义。
4. 双链合并的大分量保护与语义抽样验收线。
5. 剪贴板、URL 与信号触发补采的权限和默认开关。
6. 敏感剪贴板的内存匹配、掩码与任何派生数据保存策略。
7. 行为转移的数据契约、状态机、阈值与验收样本。
8. 弱提示的有用性反馈、频控和长期指标。
9. 「解决闭环」需要的额外结果证据及可说文案边界。
10. 双链球的建球/别名合并策略（本地自动建 provisional、LLM 候选、模糊合并阈值）。
11. 旧主题图的去留（legacy 一个版本 vs 长期保留；是否做候选导入）。
12. 个人记忆的实现与生命周期（内置 vs Hindsight；删除、导出、加密）。

## 12. 方案评审速查

每个新方案进入实施前，依次回答：

- [ ] 它服务找回、续上、理解中的哪一个真实场景？
- [ ] 哪些是观测事实，哪些是系统推断？
- [ ] 图里是否只有窗口球与双链球？有没有把主题/事件偷渡回图？
- [ ] 每条双链是否有原文出处，能否点回截图？
- [ ] 不确定时会不会弃权，而不是强行建球/合并？
- [ ] 是否能下钻回原始证据？
- [ ] 个人记忆是否只拿筛选后的内容 + 来源引用？每条是否有来源或 inferred？
- [ ] 派生数据是否可重建、可纠错、可撤销？
- [ ] 是否混淆了语义关系、成员关系与行为关系？
- [ ] 是否扩大了敏感采集或出网范围，是否已单独授权？
- [ ] 是否增加长期认知负担，生命周期如何处理？
- [ ] 是否有真实使用指标，而不只是工程测试？
- [ ] 是否可以拆成更小、更早验证产品价值的一步？

---

**最终判断标准：记忆球的成功，不是它记住了多少，而是过去的经历能否在需要时可信地回来，并且刚好帮上现在。**
