# 记忆球提案 v2：证据优先的自传体记忆

> 日期：2026-10-24｜状态：**提案（未拍板）**
> 蓝本：`docs/memory-orb-design-guide.md`（下称「指导方案」）。本提案服从它的五条设计原则；原则与本文冲突时以它为准。
> 范围：替换 M2 之后的功能组织方式。不推翻「本地优先 / 自用无云 / 弱主动强响应」，也不推翻「原始事件是唯一事实源」。
> 用法：§1 是断点清单，§11 是拍板清单。先拍 §11，再谈实施。

---

## 0. 一句话

记忆球的产品本体不是图谱，是**「问一句就能回到那一刻」**。图谱是它的地图，弱提示是它的余光。

判断标准沿用指导方案 §0：能否让真实回忆任务更快更准、能否回到原始证据、能否让人安心长期运行。

---

## 1. 与旧方案的七处断点

旧方案里有些选择是在信息不足时做的局部最优，现在有真实数据和同类产品经验，应该改。

| # | 旧做法 | 当时为什么 | 现在改成 | 代价 |
| - | - | - | - | - |
| 1 | 固定 2s 定时截屏 + dHash 去重 | 实现简单、功耗可控 | **事件驱动采集**（切窗/焦点/剪贴板/打字停顿/导航/显式手势 + 低频兜底） | 需要 WinEvent 钩子 |
| 2 | 默认只存 OCR 文本，截图可选关闭 | 存储焦虑（M1 时硬盘与压缩都贵） | **每个时刻 1 张代表帧**（960px WebP） | 约 4–8 MB/天，保留期独立 |
| 3 | 无全文索引；向量只算「被 owner 时刻引用」的事件 | 先做语义连线，检索没排进主线 | **三路召回覆盖全部事件**（FTS5 + 向量 + 结构化） | 建索引与批量向量，一次迁移 |
| 4 | `events` 只有 `app` / `window_title` | 够做窗口级记忆 | 加 `url` / `file_path` / `selection` | 采集侧解析 |
| 5 | 没有剪贴板 | 担心敏感内容 | **剪贴板是一等证据**（分类后落摘要+指纹） | 新增敏感分级与权限 |
| 6 | 节点 = 聚类（主题/时刻） | 图谱是主界面 | 新增 **Claim（记忆陈述）** 层；主题降为视图 | 数据模型改动最大 |
| 7 | 打开应用就是图谱 | 图谱是差异点 | **Ask 是主入口**，图谱是地图模式 | 界面重心迁移 |

不改变的：本地优先、自用无云、默认暂停、原始事件不可改写、派生可重建、允许说不知道、弱主动强响应、不做插件平台、不做多端。

## 2. 能力模型：三个动词 + 一条底线

| 动词 | 用户问题 | 成功判据 | 失败长相 |
| - | - | - | - |
| **找回 Recall** | 我在哪儿见过这个？ | 90 秒内命中正确事件，并能展示原文/画面 | 返回一堆相似节点却不给原文 |
| **续上 Resume** | 上次做到哪一步？ | 给出未闭环项 + 最近证据 + 下一步候选 | 生成一段通顺但无法核对的总结 |
| **理解 Understand** | 这段时间在忙什么？ | 每条概括可展开到证据 | 只有形容词，没有事件 |

**底线：Evidence or silence。** 没有证据就说「没找到」；有证据必须能点回那一刻。这条替代「AI 解说五区块」作为所有输出的统一形态。

## 3. 数据模型：Evidence / Claim / View

### 3.1 为什么要加 Claim

现在的节点是**聚类**，回答「这些经历在讲什么」。但「续上」问的是「当时发生了什么、后来怎样」，那是**陈述结构**，不是聚类结构。把陈述塞进节点 `summary` 会产生三个问题：摘要不可追溯、表达不了「未闭环」、表达不了「这条用户否掉了」。

### 3.2 三层

- **Evidence（证据）**：`events`（+ 代表帧、剪贴板条目）。只增不改，是所有下钻的终点。
- **Claim（记忆陈述）**：一句可追溯的话，派生但有自己的身份。它是「续上」和「理解」的原子。
- **View（视图）**：`moments` / 主题 / 日周月年 / 地图节点。纯投影，可重建、可版本化。

```sql
claims(
  id, text, kind,          -- fact / action / outcome / open_loop
  subject,                 -- app / project / file / url
  ts_start, ts_end,
  evidence,                -- JSON: [{type:'event'|'moment'|'clip', id}]
  confidence REAL,
  source TEXT,             -- rule / llm / user
  state TEXT,              -- candidate / accepted / rejected / superseded
  supersedes INTEGER,      -- 同主语的后续陈述（"后来解决了"）
  created_at
)
```

约束（承接指导方案）：

- Claim 至少 1 条 evidence，否则只能是 `candidate`，且**不得触发提示**。
- 用户拒绝的 Claim 不删，标 `rejected`，作为负样本（指导方案 §5.6）。
- 同一 `subject` 下 `open_loop` 且未被 `superseded` 的集合 = **未闭环清单**。这是「续上」的直接答案，也是第一个能立刻感知价值的功能。
- `moments` 补 `builder_version`（指导方案 §11.1），切分规则变更时可重建而不动 L0。

### 3.3 迁移

`nodes` 保留为主题视图，`source_events` 继续服务下钻；`claims` 新增表；`theme_moments` 不动。不需要一次性重写图谱。

## 4. 采集：事件驱动的证据流

### 4.1 触发矩阵

| 触发 | 语义 | 采什么 | 备注 |
| - | - | - | - |
| 应用/窗口切换 | 新的工作上下文 | 帧 + 文本 | 必采 |
| 窗口内焦点变化 | 子上下文切换 | 元数据，延迟 300ms 采帧 | 去抖 |
| 剪贴板变化 | 内容流动的起点 | 剪贴板条目 + 当前帧 | 与事件同时刻对齐 |
| 打字停顿 ≥1.5s | 输入完成 | 只取差异文本，不采帧 | 省资源 |
| 导航（URL 变化） | 浏览路径 | URL + 标题 + 帧 | 浏览器优先 |
| 显式手势 | 用户认为重要 | 全量文本 + 帧 + 标注 | Alt+Space / 双击球 |
| 空闲兜底 | 防止零记录 | 60s 一次 | 仅在前台无变化时 |

为什么改：2s 定时的真正问题不是冗余，是**漏短瞬态**——菜单、弹窗、提示条、一闪而过的报错，而这恰恰是「见过」最常发生的地方。

### 4.2 文本源：UIA 优先，OCR 兜底

- 先走 Windows UIA，拿结构化文本（role / name / value / bounds）；`IsPassword` 的元素**不取文本**，只记「此处有密码框」。
- 超时 500ms，失败或文本为空 → 回退现有 WinRT OCR（2× 放大保留）。
- 记 `text_source`，用于算覆盖率与排障。
- 收益：小字号/低对比度/代码不丢；结构化后去噪、归纳 token 更省；CPU 通常低于 OCR。
- 风险：Chrome / Electron 的 UIA 树极大，必须 worker + 深度上限 + 应用白名单降级。

### 4.3 代表帧

- 每个时刻存 1 张缩略图（最长边 960，WebP q70 ≈ 60–120KB）。
- 估算：60 个时刻/天 ≈ 4–8MB/天，保留 30 天 ≈ 150–250MB。
- 理由：文本能搜索，**画面才能「认出来」**。指导方案 §7 要求点开后看到「原始记录」，纯文本是残疾的证据链。
- 隐私：整帧敏感判定、密码/黑名单应用不存帧、可与文本用不同的保留期。

### 4.4 剪贴板 / URL / 文件路径

- **剪贴板**：明文默认不落库，只存「首 200 字符摘要 + 内容哈希 + 敏感级别」；敏感内容只在内存内做短时匹配（指导方案 §5.7）。
- **URL**：从浏览器窗口标题 / 地址栏 UIA 取；query 里的 key、token、token 类参数入库前剥离。
- **文件路径**：从 VS Code / Office / 编辑器的窗口标题模式提取，作为 Claim 的 `subject`。

### 4.5 覆盖率面板

「今天记到了哪些应用、各多久、有没有空洞」。信任来自可见性：用户要能自己看出系统漏了什么，而不是等它出错。

## 5. 检索：三路召回，答案是证据卡

| 路 | 实现 | 覆盖 |
| - | - | - |
| 关键词 | FTS5 `trigram`（≥3 字命中）+ `LIKE` 兜底（2 字） | 精确词、报错、文件名 |
| 语义 | `bge-small-zh` 向量，**全部事件**（不只 owner 时刻） | 换个说法也能找到 |
| 结构 | 同 app / 同标题 / 同 URL 的时间邻域 | 「就在那前后」 |

- 融合用 RRF，不做黑箱加权。
- 过滤维度：时间、应用、标题、URL、是否敏感。
- **答案形态是证据卡**：时刻 + 代表帧 + 原文片段（命中词高亮）+ app/时间 + 「为什么命中」。AI 只在证据卡集合内组织一句话，每个分句可点回证据（指导方案 §6 的三层表达）。
- 明确不做：让 AI 先总结、再让你相信。**先检索，后组织**。

这一节同时是 Ask 面板和弱提示的引擎，必须一份实现两处复用。

---

## 6. 弱提示：从「复制触发」升级为「上下文指纹」

- **指纹** = 前台 app + 窗口标题 + 选中文本 + 剪贴板 + 最近文件路径 + 最近导航 URL。
- 本地检索（**不调用云**）→ 置信够高且有排他来源 → 脉冲一次。
- 卡片给三样：一句话、3 条证据、「为什么出现」。
- 频控：同类 24h 一次、静默时段、忽略即降权；一次最多一个提示。
- 指标：有用率、提示后找回率、误提示/天（不把点击率当价值）。

---

## 7. 图谱：从「星尘」变成「地图」

现有 Foam 全局图保留，但角色改变：

- **打开时聚焦「当前上下文邻域」**：仍是同一张图，只是初始相机框在今天 + 当前项目 + 最近活跃主题上，而不是全量星尘；不是第二张图，也不按日割裂（指导方案 §4.1 不变）。
- **全局图 = 地图模式**：看全貌、找跨度，需要显式切换。
- **时间轴与图谱联动**：scrub 时节点随日期淡入淡出（现有日历筛选升级为连续轴）。
- **生命周期**：活跃 / 休眠 / 归档；沉没主题淡出邻域，但仍可搜索、可展开（指导方案 §3.2）。
- **点节点 → 证据卡**（与 §5 同一组件），不再是摘要弹窗。
- 主题连线仍由本地向量决定，LLM 不生成语义边（D27 不变）。

## 8. 信任：可验证的边界

- **出云收据**：每次云端调用写一条本地记录——时间、供应商、模型、脱敏后文本的哈希、命中的脱敏规则、token 数。用户随时能查「今天到底发出去了什么」。
- **fail closed**：过滤器不可用就拒绝调用，不降级成明文（指导方案 §2.4）。
- **降级矩阵**：无模型 → 关键词检索仍可用；无向量 → 图谱仍可用；无 UIA → OCR；无权限 → 明示横幅。系统任何单点缺失都不能表现为「什么都没记住」。
- **暂停**：停采集 + 停归纳 + 停提示 + 停出网，覆盖所有新增信号（在 D18 基础上扩到提示与检索）。

---

## 9. 验收

- **真实回忆题集**：自建 20 题（内容型 / 时间型 / 来源型各若干），每周跑一次，记录是否 90 秒内命中、来源是否正确。
- **产品指标**：首次命中率、90 秒完成率、来源正确率、未闭环清单准确率、误提示/天。
- **工程指标**：CPU、常驻内存、单次检索 P95、出云量与 token。
- 工程闸门（test / typecheck / build / e2e）不变，但它只证明系统没坏，不证明产品有用（指导方案 §8.1）。

## 10. 路线：按能力闭环，不按旧里程碑

| 阶段 | 交付 | 出口 |
| - | - | - |
| **P1 证据完整性** | 触发矩阵 + UIA 兜底 + 剪贴板/URL + 代表帧 + 覆盖率面板 | 一天下来，覆盖率 ≥95%，无空洞日 |
| **P2 找回** | FTS + 全量向量 + Ask 面板 + 证据卡 | 题集 20 题里 ≥15 题 90 秒内命中 |
| **P3 记忆陈述** | Claim 抽取 + 未闭环清单 | 清单里 ≥80% 被用户认可为真 |
| **P4 弱提示** | 上下文指纹 + 脉冲 + 反馈 | 误提示 ≤3/天，有用率 ≥50% |
| **P5 地图** | 邻域视图 + 时间轴 + 生命周期 | 缩小能看全貌，放大能回到那一刻 |

现有图谱不是重做，是 P5 里降级为地图并补邻域/时间轴。

---

## 11. 需要拍板的八件事（按阻塞排序）

1. **代表帧默认开启**（覆盖「截图默认不存」的立项决策）。
2. **采集触发矩阵**，含剪贴板/焦点/URL 的默认开关（覆盖「2s 定时」的实现前提）。
3. **UIA 原生桥**：新增原生依赖与风险，值不值得先做一天的 A/B。
4. **Claim 层**：数据模型最大的一次改动，接不接。
5. **Ask 成为主入口**：界面重心从图谱移到问句；同时以证据卡替换 D9 的「解说五区块」。
6. **全事件向量**：磁盘与 CPU 成本换召回覆盖。
7. **出云收据**：记什么、留多久、是否含哈希。
8. **提示扩展为上下文指纹**：从「复制触发」放宽到「当前上下文」。
